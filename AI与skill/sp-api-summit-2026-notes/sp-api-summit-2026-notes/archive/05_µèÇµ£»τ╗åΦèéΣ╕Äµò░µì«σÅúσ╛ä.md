## 财务接口七项清单

以下为本次目录中的 Finances 七项操作，均为读取。新旧接口可能覆盖相同业务事件，不可将两套数据简单相加。

| 版本 | 操作 | 请求路径 | 用途 |
|---|---|---|---|
| 2024-06-19 | listTransactions | /finances/2024-06-19/transactions | 交易 收费 退款等明细 |
| 2024-06-19 | listBalances | /finances/2024-06-19/balances | 当前或历史余额 |
| 2024-06-19 | listSummary | /finances/2024-06-19/summary | 期间或结算汇总 |
| v0 | listFinancialEventGroups | /finances/v0/financialEventGroups | 财务事件分组 |
| v0 | listFinancialEventsByGroupId | /finances/v0/financialEventGroups/{eventGroupId}/financialEvents | 组内明细 |
| v0 | listFinancialEventsByOrderId | /finances/v0/orders/{orderId}/financialEvents | 订单相关明细 |
| v0 | listFinancialEvents | /finances/v0/financialEvents | 按条件读取财务事件 |

参考：[Finances 总览](https://developer-docs.amazon/sp-api/docs/finances-api)、[交易明细参考](https://developer-docs.amazon/sp-api/docs/finances-api-v2024-06-19-reference)、[listSummary](https://developer-docs.amazon/sp-api/reference/listsummary)。

**财务数据能辅助对账，不能单独算出完整净利润。**采购、头程、包装、税务处理、汇率、站外成本及广告消耗分摊需要补齐。订单净额不等于利润；费用优惠抵扣到零不等于费用永久取消。

按首次记账分析经营收支与按释放日期分析现金流，是两种不同报表。出现 DEFERRED_TRANSACTION_ID、RELEASE_TRANSACTION_ID 等关联时，要核验原始交易与释放交易的关系，避免重复计收入；不能无条件删除所有释放记录，因为原始交易可能在其他期间。

`listTransactions` 官方提示可能未包含最近 48 小时的订单财务记录。这是完整性与时效限制，不能扩展为“所有财务接口都延迟 48 小时”或“48 小时内金额必然错误”。分页要读到结束，空页也可能仍有下一页。

## 可用 暂缓和到账

余额可能包含 AVAILABLE（可用）、RESERVED（预留）及其下层 DEFERRED（暂缓）、ACCOUNT_LEVEL_RESERVE（账户级预留）。核对层级后再求和，不能把父项与子项重复相加。

暂缓的常见原因包括配送日期预留 DD7，以及企业买家账期 B2B。DD7 通常与送达后预留期有关，不是等待买家手动点击确认收货；企业账期则可能等待买家支付发票。预计释放日期也不是银行到账日期。

资金通常经历“暂缓 → 释放 → 纳入结算付款 → 银行到账”。余额少不等于违规冻结。费用支付还取决于卖家扣款方式及广告账单设置；负余额不代表无限赊账，付款失败可能影响广告或账户使用。具体应核对到期账单、备用付款方式和后台通知，而不是仅凭余额判断。

参考：[亚马逊暂缓交易说明](https://sellercentral-europe.amazon.com/seller-forums/discussions/t/3fe1fff3-f924-42bc-aa45-69244e8d6f83)、[广告付款方式说明](https://advertising.amazon.com/library/news/update-on-advertiser-payments)、[卖家负余额处理说明](https://sellercentral.amazon.com/seller-forums/discussions/t/6e57e55b-9a25-4a8e-a6cd-e837040ec33f)。

## 四种分析报表

| 报表类型 reportType | 业务用途 | 主要权限或资格 |
|---|---|---|
| GET_BRAND_ANALYTICS_SEARCH_QUERY_PERFORMANCE_REPORT | 搜索词与商品的曝光 点击 加购 购买份额 | Brand Analytics 及品牌注册资格 |
| GET_BRAND_ANALYTICS_SEARCH_CATALOG_PERFORMANCE_REPORT | 商品搜索转化过程 | Brand Analytics 及品牌注册资格 |
| GET_COUPON_PERFORMANCE_REPORT | 领券 用券 折扣 预算和销售表现 | 卖家 Brand Analytics 角色 |
| GET_PROMOTION_PERFORMANCE_REPORT | 促销浏览 销量和销售表现 | 卖家 Selling Partner Insights 角色；供应商要求另核对 |

搜索查询报表必填 reportOptions.asin；商品搜索报表可选 reportOptions.asins，两者不要混写。前两类支持周、月、季度，按周使用周日至周六，单次不跨多个周期。搜索表现不能直接当广告效果或全店流量。

优惠券和促销按活动开始日期筛选，可能返回跨月活动累计表现，并非按筛选月份切片。两类每日更新。卖家促销效果报表当前列出的覆盖为 Best Deal、Lightning Deal，不应假定全部优惠形式都包含。

参考：[品牌分析报表及参数](https://developer-docs.amazon/sp-api/docs/report-type-values-analytics)、[促销及优惠券报表](https://developer-docs.amazon/sp-api/docs/report-type-values-performance)。

通用调用链：

| 操作 | HTTP 与路径 | 说明 |
|---|---|---|
| getReports | GET /reports/2021-06-30/reports | 查已有报表 |
| createReport | POST /reports/2021-06-30/reports | 生成报表任务，不是创建促销 |
| getReport | GET /reports/2021-06-30/reports/{reportId} | 查状态及文档标识 |
| getReportDocument | GET /reports/2021-06-30/documents/{reportDocumentId} | 取下载信息，再下载并按需解压 |


## 身份与权限辨别

| 概念 | 白话解释 | 如何确认 |
|---|---|---|
| Seller 第三方卖家 | 通过平台向消费者销售 | Seller Central 后台及卖家业务授权 |
| Vendor 供应商 | 向亚马逊供货，由亚马逊零售 | Vendor Central 供应商合同和采购订单 |
| SPN 服务商网络 | 面向卖家提供服务的机构网络 | 服务商申请及审核，不是商品销售身份 |
| Brand Registry 品牌注册 | 品牌相关资格体系 | 品牌后台及关联角色 |
| SP-API Role 应用角色 | 软件可访问哪些业务资源 | 开发者资料 应用配置及重新授权情况 |

使用 FBA 不会把 Seller 变为 Vendor。公司可能同时有卖家与供应商业务；确认其中一个账户类型，不能排除公司另有另一类账户。品牌分析可读也不能证明操作人是品牌所有者或管理员。

供应商指标中的 vendor confirmation rate（供应商确认率）、shipped COGS（亚马逊采购成本视角的已发货成本）、预测分位数等，不应直接套用到卖家利润分析。预测也不是实际销量。

角色不是唯一身份标签，一个应用可以拥有多项权限。读取报表列表返回 200，不足以证明可以生成任意报表；列表为空既不能证明没权限，也不能证明没有业务。新增角色可能需要开发者审核、更新应用并重新授权。

参考：[SP-API 角色定义](https://developer-docs.amazon/sp-api/docs/roles-in-the-selling-partner-api)、[Seller Central 与 Vendor Central 区别](https://sell.amazon.com/tools/seller-central)。
