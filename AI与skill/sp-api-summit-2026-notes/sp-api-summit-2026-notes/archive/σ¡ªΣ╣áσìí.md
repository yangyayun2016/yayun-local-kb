# 新人学习卡与实践清单

> 本页是基于照片内容设计的会后学习材料，例子为教学假设，不是大会讲师的逐字发言，也不是你的店铺实测数据。

## 一、先认识这些词

| 术语 | 白话解释 | 简单例子 |
|---|---|---|
| API | 软件之间交换信息的接口 | ERP 自动读取订单 |
| SP-API | 亚马逊销售伙伴业务接口集合 | 查询商品、订单或相关经营数据 |
| Ads API | 广告数据与操作接口 | 读取某活动花费与归因销售 |
| MCP | AI 客户端连接外部工具的约定 | AI 连接查询文档的工具 |
| ERP | 管理订单、商品、库存等业务的软件系统 | 把多个店铺信息放到一起处理 |
| ASIN | 亚马逊商品编码 | 标识一个具体商品或变体 |
| 父／子 ASIN | 变体系列与具体变体 | 一个系列下的不同颜色 |
| SKU／MSKU | 卖家自己的商品管理编码 | 给蓝色款起一个仓库可识别的编号 |
| FNSKU | 亚马逊物流相关库存识别码 | 用于库存识别，不能直接当作 ASIN |
| Marketplace | 站点／商城 | 美国站与德国站分开分析 |
| AB／B2B | 企业购／企业对企业销售 | 企业采购办公室耗材 |
| PO | 采购订单编号 | 公司用采购编号核对包裹 |
| FBM | 卖家自配送 | 卖家安排仓库与承运人发货 |
| FBA | 亚马逊物流 | 使用相关亚马逊仓储配送服务 |
| MCF | 多渠道配送 | 为不同销售渠道订单安排配送 |
| Sandbox | 沙盒测试环境 | 模拟包裹延误，不操作真实订单 |
| Webhook | 事件发生后主动发通知 | 包裹签收后系统收到状态变化 |
| Schema | 数据结构定义 | 说明订单有哪些字段、各是什么类型 |
| PII | 可识别个人的信息 | 买家的姓名、地址 |
| RDT | 受限数据令牌 | 部分受限数据访问流程中的凭证 |
| FOEP | 推荐报价预期价格 | 定价参考，不能保证获得购物车 |
| Sessions | 会话次数 | 按平台定义统计的一次访问会话，不等于独立人数 |
| Page views | 页面浏览次数 | 同次访问可浏览多个页面 |
| Attribution window | 归因窗口 | 广告互动后一定时间内的购买被计入广告结果 |
| ACoS | 广告花费占广告归因销售额的比例 | 花 20、归因销售 100，则为 20% |
| TACoS | 广告花费占整体销售额的比例 | 花 20、整体销售 200，则为 10% |

## 二、把知识转成操作步骤

### 学习卡 A：企业购标签核对

**适用场景：**企业客户反馈包裹难以对应采购单。

**步骤：**确认企业购订单 → 核对 PO 字段 → 核对收货公司 → 比对 ERP 展示 → 比对承运人标签。

**判断标准：**原始订单、ERP、标签上的关键内容一致；缺失项明确提示；字段太长不会悄悄截断关键信息。

**常见错误：**只有公司名称，没有 PO；订单数据已更新但标签仍使用旧缓存；把现场示例当成所有承运人通用字段。

### 学习卡 B：促销巡检

**适用场景：**活动建好了，但部分商品没有出现预期优惠。

**步骤：**搜索活动 → 看完整活动状态 → 查询全部商品选择页 → 找到商品级问题 → 回后台核对商品资格与买家端展示。

**判断标准：**活动 ID、站点、起止时间、商品范围、优惠条件一致；能够解释是活动层问题还是商品层问题。

**常见错误：**只查第一页；把活动正常当成所有商品正常；把满减直接扣到每件商品上；把能查询误认为能修改。

### 学习卡 C：整体销售与广告拼表

**适用场景：**想判断销量变化与广告投入是否有关。

**步骤：**定账号／站点／完整日期／币种 → 定子 ASIN 或 SKU 粒度 → 先汇总广告 → 关联整体销售 → 查重复与缺失 → 计算指标 → 写证据与待验证原因。

**判断标准：**关联前后整体销售总额不被放大；各字段单位清楚；广告窗口和数据更新时间可见；分母为零不输出误导比例。

**常见错误：**把 sales7d 当作全部销售；订单数当件数；把所有活动行上的整体销售加总；当天未完整数据与完整日直接比较。

## 三、三个优先练习

1. **读懂业务：**从促销章节找出“活动状态正常但商品优惠缺失”应该查的下一层数据，用一句话解释原因。
2. **发现异常：**画一个商品日级表，写出站点、日期、ASIN、整体销售、广告花费、广告归因销售及各自口径。
3. **验证结果：**有真实数据后，选一个商品，对照后台和报表写一次“事实—假设—待查—动作—验证”的复盘。

## 四、先判断，再看解析

### 题 1：自然销量能不能直接相减？

假设某天总销量 100 件，广告报表 `orders7d` 为 30。能否得出自然销量 70 件？先写出你的理由。

> **展开解析**
> 不能。总销量是件数，orders7d 是订单数，而且日期、归因窗口、商品归属仍可能不同。先找同口径的广告件数字段并确认归因逻辑；无法对齐时，不输出精确自然销量。

### 题 2：这件商品现在便宜了多少？

某商品标价 14.79 美元，提示“选定商品满 30 美元减 5 美元”。能否直接把这件商品的成交价记成 9.79 美元？

> **展开解析**
> 不能。优惠有门槛和适用商品条件，还需要确定订单如何满足条件、优惠如何分摊。记录原价、促销形式、门槛与适用范围，比强行写一个无条件折后价更准确。

### 题 3：AI 已经把迁移做完了吗？

AI 列出了四个 Java 文件的 Critical 问题并给出修改方向，是否表示迁移完成？

> **展开解析**
> 不表示。照片证明的是分析过程。还需要确认正式目标版本、实施修改、编译、测试订单创建／取消／追踪、处理失败和回滚。本次资料里正式演讲页与演示目标版本还不同。

## 六、可复用的 AI 提示词

```text
请根据我提供的店铺报表分析一个商品。
先核对账号、站点、币种、时区、日期是否完整，区分订单数与销量件数、整体销售与广告归因销售。
广告归因窗口不一致时，先说明哪些指标不能直接相减或比较。
按店铺风险、销售、广告、库存、今日行动的顺序组织。
每个结论标注证据，区分已确认事实、合理假设、待验证信息。
最多给出三个优先动作，每个都写今天怎么做、下一次怎么验证。
没有的数据明确写缺失，不从会议示例中补造店铺数据。
```
