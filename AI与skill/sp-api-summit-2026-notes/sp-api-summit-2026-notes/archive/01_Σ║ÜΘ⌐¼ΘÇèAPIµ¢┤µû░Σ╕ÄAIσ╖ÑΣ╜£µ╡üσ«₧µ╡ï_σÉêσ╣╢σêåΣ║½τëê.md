## 一 更新了什么 对业务有什么用

### 先分清四种状态

“大会提到”“官方发布”“某个授权可用”“已通过生产验证”不是同一件事。本文的实测来自不同对话形成的操作记录，合并时分别标注范围，没有把不同测试视为同一次执行。本次整理未重新连接店铺执行这些业务测试。

SP-API 是 Selling Partner API，即销售伙伴业务接口。它连接订单、库存、商品、财务等业务。广告投放中的 SP 是 Sponsored Products，含义不同；广告活动及效果数据主要通过 Amazon Ads API 获取。

### 与大会投影片怎么对应

**订单。**新版本可通过 includedData 选择需要的数据，减少多次调用。“一次获取完整信息”仍受权限、分页和业务状态限制。PII（可识别个人的信息）仍受角色控制；新 Orders 不要求额外 RDT（受限数据令牌），不代表所有 SP-API 都取消 RDT。现场 URL 示例与 Python SDK 写法不同，迁移不能只替换路径。[Orders 迁移指南](https://developer-docs.amazon/sp-api/docs/orders-api-migration-guide)

**商品。**getListingsItem 和 searchListingsItems 支持同一区域多站点读取。会议指出搜索筛选及排序以首个站点为主；报表中要保留站点维度，不能理解成对全球站点分别执行了相同查询。

**促销。**searchPromotions 看活动摘要，getPromotion 看完整详情，getProductSelection 看参与商品与商品级问题。现场称读取在 9 月初推出，官方发布日志列于 8 月 26 日，两种口径保留。创建更新在会场被列为未来计划，本批没有完成写入测试；不能从读取可用推导出当前可以批量修改活动。

**定价。**getCompetitiveSummary 展示相似商品及促销信息，FOEP（推荐报价预期价格）提供争取推荐报价的价格参考。满额优惠不能逐件直接扣减，按参考价格调价也不保证取得购物车。

**企业购与履约。**PO（采购单）编号及收货公司名称可帮助企业客户核对包裹。Easy Ship 获取取件时段不等于完成预约。MCF（多渠道配送）面向多渠道订单履约，不能与普通站内 FBA 买家订单混为一套业务。

**MCF 版本。**正式演讲页为 v2026-07-04，AI 迁移演示出现 v2025-09-24 预发布版本。本篇不拼接两套字段作为可运行规范。BHDR、佣金及物流服务商参与问题仍缺足够材料，不能写成已发布政策。

## 二 官方 MCP 与 JSON 工作流怎样配合

### 五个组件各负责什么

| 组件 | 白话解释 | 例子 |
|---|---|---|
| AI Agent | 理解需求、选择工具并解释结果的助手 | 理解“查昨天销售，再对账” |
| MCP | AI 与工具沟通的协议 | 把查询需求交给外部工具 |
| SP-API | 亚马逊业务接口体系 | 读取库存、订单、财务 |
| Reports API | 按预设类型生成或读取报表 | 获取促销效果报表 |
| Data Kiosk | 在支持的数据集中按字段和条件查询 | 只取某完整日期的销售汇总 |

官方 Local MCP 包含两个可独立使用的服务器。开发助手负责找接口和发起请求；工作流服务器负责保存及运行多个步骤。它们是官方集成示例，生产使用仍需要团队测试、维护与权限控制。[官方安装说明](https://github.com/amzn/selling-partner-api-samples/blob/main/use-cases/sp-api-dev-mcp/README.md)

### 开发助手的六个工具

| 工具 | 主要用途 |
|---|---|
| sp_api_reference | 检索官方文档 |
| sp_api_explore_catalog | 查看路径、参数、响应结构与目录 |
| sp_api_execute | 执行获授权的真实业务请求 |
| sp_api_generate_code_sample | 辅助生成 SDK 代码示例 |
| sp_api_migration_assistant | 分析版本迁移与代码变化 |
| sp_api_optimize | 检查分页、限流、缓存及错误处理等集成问题 |

一组目录测试记录了 57 个业务类别、370 条 HTTP 方法与路径记录，按 endpoint ID 去重为 349 个。这是特定环境的目录快照，不是最新官方总量，也不代表拥有全部权限；该快照未列入近期 Promotions 类别。完整原名及条目数保留在独立附录。

### 工作流如何运行

业务目标 → AI 查接口与参数 → 创建或复用 JSON → 校验流程 → 本地执行器调用接口 → 保存结果与日志 → AI 解释结果。

JSON 用状态和转移规则描述步骤；ASL 是 Amazon States Language。此次本地工作流服务器使用 Node.js 执行器，并提供等待、分支、文件获取、暂停恢复和人工输入等工具。某批连接记录发现 30 个工具，这只是该版本的观察值。

Data Kiosk 查询是异步的：创建查询后等待完成，再获取文档下载地址，下载 JSONL 文件。JSONL 的每一行是一条 JSON 数据，便于逐条解析。提交成功只表示任务已受理，不能代替完成状态和文件内容校验。

**本地 JSON 与云端 JSON 不一定通用。**官方云端示例使用 AWS Step Functions 调度 Lambda；本地执行器支持的任务资源不同。此次测试中，AWS 示例原样导入成功，但运行时因不支持 Lambda 资源而失败，适配成本地任务后才跑通。

已有流程可查找、查看定义、导入、校验和执行。导出 Mermaid 流程图或独立 Node.js 脚本的能力在源资料中通过工具及源码确认，但没有单独执行导出脚本。保存流程也不会自动创建每日定时任务。

### 三种版本分开记

Data Kiosk API v2023-11-15 是接口版本；analytics_salesAndTraffic_2024_04_24 是数据集结构版本；1.0.5 是本批 npm 工具包版本。源资料还记录 2025-08-27 新增 salesAndTrafficTrends 趋势查询，但本批工作流使用按日期汇总，未实测趋势查询。

## 三 接入与授权需要准备什么

### 本地 MCP 不是一个公网网址

npm 是软件安装渠道。这个 MCP 在本机启动，通过 stdio（标准输入输出）与 AI 客户端通信，再通过 HTTPS 请求亚马逊。因此无需先申请公网 MCP 地址。本地运行仍需联网；数据进入 AI 客户端后如何处理，取决于所用平台及设置。

以下保留本批测试使用的固定版本示例，不表示该版本永远最新。运行环境为 Node.js 20 或以上。

```bash
npm install -g @amazon-sp-api-release/sp-api-dev-mcp@1.0.5

# 开发助手
sp-api-dev-assistant-mcp-server

# 工作流服务器
sp-api-workflow-mcp-server
```

将相应命令注册到 MCP 客户端，通过受控配置注入参数。下面仅列变量含义，不附带真实凭证。

| 配置 | 用途 |
|---|---|
| SP_API_CLIENT_ID | 应用客户端编号 |
| SP_API_CLIENT_SECRET | 对应应用密钥 |
| SP_API_REFRESH_TOKEN | 卖家授予该应用的长期授权凭证 |
| SP_API_REGION | 按实际区域选 na、eu 或 fe |
| SP_API_BASE_URL | 对应区域的公开 API 地址 |

NPM_TOKEN 属于发布软件包到 npm 的流程，普通用户安装公开包不需要申请；它不是店铺授权令牌。

### 应用编号和令牌不要混用

Application ID 用来标识 SP-API 应用，Client ID 与 Client Secret 用来识别 OAuth 客户端，Refresh Token 代表特定卖家给该客户端的授权，Access Token 则是调用时使用的短期令牌。

LWA（Login with Amazon）是亚马逊的授权实现。建立安全配置文件不会自动获得卖家业务权限，刷新令牌也不能跨客户端混用。测试中曾出现 unauthorized_client，更换为对应应用凭证后成功换取访问令牌；单看错误码不能判定所有同类失败都出于同一个原因。

### 自授权和公共应用授权

| 方式 | 适合场景 | 关键步骤 |
|---|---|---|
| 自授权 | 自己有资格授权的账号进行接入测试 | 在应用管理中授权，安全保存刷新令牌 |
| 公共应用 OAuth | 让其他卖家接入自己的应用 | 注册登录与回调地址，验证 state，及时兑换授权码，按卖家隔离令牌和数据 |

公共应用可用自授权测试；但自授权成功不等于网站回调已通过验证。其他卖家不需要获得开发者的 Client Secret。回调网址背后必须有处理程序，仅填一个地址不构成完整授权服务。

刷新令牌是长期、可撤销的凭证；公共应用还涉及定期重新授权要求，应按应用类型及官方通知管理，不能承诺永久有效。自动换取 Access Token 也不等于可以自动恢复已撤销的卖家授权。[公共应用授权](https://developer-docs.amazon/sp-api/docs/authorize-public-applications) · [重新授权](https://developer-docs.amazon/sp-api/docs/renew-authorizations)

### Seller Vendor 品牌与广告权限

Seller 是第三方卖家，Vendor 是向亚马逊供货的供应商。使用 FBA 不会把 Seller 变为 Vendor；企业客户使用 PO 也不会改变卖家身份。公司可以同时开展不同业务。

Brand Registry 是品牌资格体系，SP-API Role 是应用可访问的资源范围，SPN 是服务商网络。它们不能互相替代。能读取某品牌报表，也不证明操作人就是品牌所有者。供应商指标中的确认率、已发货采购成本和预测分位数，不宜直接套到普通卖家利润分析。

SP-API 授权成功不等于广告授权成功。欧洲 SP-API 与 Ads API 地址分别是 sellingpartnerapi-eu.amazon.com 和 advertising-api-eu.amazon.com；后者的账户列表请求还需要广告鉴权。

## 四 实测到了哪一步

### Data Kiosk 工作流的完整过程

1. 明确站点、完整日期、聚合维度和目标字段。
2. 创建查询，等待后获取处理状态，设置有限轮询与失败分支。
3. 确认查询完成及结果文档存在，获取下载地址。
4. 下载 JSONL，检查文件存在并可解析。
5. 到卖家中心按同站点、同日期和同筛选条件核对。

原工作流记录为约 33 秒、1 条日汇总结果。该耗时包含本次流程的等待设置，只是一次运行观察，不是效率提升比例或性能保证。

核对字段为 orderedProductSales（销售额）、unitsOrdered（订购件数）、totalOrderItems（订单商品项数）。最后一项不是去重订单数，实际经营数值不公开。

过程中曾遇到网络连接重置、查询列表为空，以及最初后台站点或日期不一致。恢复连接、创建查询并统一筛选口径后，下载及三项对账成功。空列表不能解释为店铺没有销售；导入成功也不能解释为流程一定可执行。

### 余额差异的排查结论

C 批先核对站点、币种与账户类别，再检查 lastUpdatedTime 和本地请求路径，并绕过 MCP 向官方区域端点直接发起两次只读查询。

两次直连均返回 HTTP 200；请求标识不同、HTTP Date 变化、X-Cache 显示 Miss from cloudfront，但余额和 lastUpdatedTime 未变。已检查的 MCP 业务路径没有发现余额缓存，工具展示也未完整保留原始响应头。

**可以确认：**旧余额不只出现在 MCP 中，直连也能复现，不能把问题简单归咎于 MCP 独有缓存。

**尚不能确认：**亚马逊内部是否还有其他缓存、准确刷新周期、页面差额对应哪些交易，或差异是否涉及其他业务口径。此批没有完成后台与接口的逐笔对账。

记录请求时间、HTTP Date、业务数据的 lastUpdatedTime，可以区分“刚发出的请求”和“返回的是何时更新的数据”。数据更新时间由服务端返回；重复调用不等于强制刷新。

## 五 运营可以怎样使用这些数据

### 把数据对应到五个业务问题

| 问题 | 主要数据 | 还要补什么 |
|---|---|---|
| 店铺有没有风险 | 商品问题、订单与履约异常 | 账户绩效、政策通知、工单和退货详情 |
| 卖得怎么样 | 订单、销量、销售额、流量 | 完整日期、订单状态、前日与上周同日基线 |
| 赚不赚钱 | 交易、费用、退款、净销售 | 采购、头程、包装、汇率、税务及外部成本 |
| 广告有没有浪费 | Ads API 花费与归因销售，结合整体销售 | 商品利润、归因窗口、投放目的与搜索词 |
| 库存是否安全 | 可配送、预留、不可售及在途库存 | 销量、补货周期和到货可靠性 |

### 财务接口用于对账 不直接等于利润

Finances 2024-06-19 包含 listTransactions、listBalances、listSummary。目录中另有 v0 的财务事件组、按组明细、按订单明细及财务事件列表，共七项读取操作。新旧接口可能覆盖同一业务事件，不能简单叠加。Transfers 的付款查询是另一个模块。

交易中出现 DEFERRED_TRANSACTION_ID、RELEASE_TRANSACTION_ID 等关联时，要检查原始记账与资金释放之间的关系。按交易记账看经营收支，按释放或付款时间看现金流，回答的是不同问题。既不能重复计收入，也不能无条件删掉全部释放记录。

listTransactions 文档提示可能未包含最近 48 小时的订单财务记录；这不是“所有财务接口统一延迟 48 小时”。分页应读到结束，空页仍可能有下一页。[交易接口参考](https://developer-docs.amazon/sp-api/docs/finances-api-v2024-06-19-reference)

余额中的 AVAILABLE（可用）、RESERVED（预留）以及其下层暂缓、账户级预留，要看清层级后再求和，避免父项与子项重复累计。预计释放日期不等于银行到账日期；暂缓也不能仅凭名称认定是违规冻结。

源资料提及配送日期预留及企业购账期。具体释放规则、扣费方式、付款失败影响，应结合账户通知和政策核对。费用优惠抵扣到零不代表费用永久取消，广告付款记录也不等于对应投放日期的广告消耗。

### 四种值得了解的分析报表

| reportType | 用于回答什么 | 权限与口径重点 |
|---|---|---|
| GET_BRAND_ANALYTICS_SEARCH_QUERY_PERFORMANCE_REPORT | 搜索词与商品的曝光、点击、加购、购买份额 | 品牌资格及 Brand Analytics；reportOptions.asin |
| GET_BRAND_ANALYTICS_SEARCH_CATALOG_PERFORMANCE_REPORT | 商品在搜索过程中的转化表现 | 品牌资格及 Brand Analytics；可选 reportOptions.asins |
| GET_COUPON_PERFORMANCE_REPORT | 领券、用券、折扣、预算与销售 | 按适用主体和角色核验 |
| GET_PROMOTION_PERFORMANCE_REPORT | 活动浏览、销量与销售表现 | 卖家角色与供应商要求分别核验 |

源资料记录：前两类按周、月、季度组织，周口径为周日至周六；优惠券和促销按活动开始日期筛选，可能返回跨月累计表现，不是简单的月份切片。具体期限、字段及支持活动类型以所选报表文档为准。[品牌分析报表](https://developer-docs.amazon/sp-api/docs/report-type-values-analytics) · [促销效果报表](https://developer-docs.amazon/sp-api/docs/report-type-values-performance)

标准流程是查已有报表，必要时创建任务，检查任务完成，再获取下载信息并下载、解压、解析。createReport 虽然使用 POST，但用途是生成分析任务，不是创建促销活动。反过来，也不能把所有 POST 都当成无业务影响的查询。

### 整体销售与广告先对齐 再计算

SP-API 可出现广告付款信息，也可提供品牌搜索及促销分析数据；活动、关键词、出价、搜索词花费和广告归因结果仍需 Ads API 或广告报表。二者先按同账号、站点、日期与商品粒度聚合，再关联，避免一个商品的多条广告活动把总销售重复计算。

ACoS 的分母是广告归因销售额，TACoS 的分母是整体销售额。订单数、件数、订购销售额、净销售额和投放日／归因日不能混算。会议中的“总销量减广告销量”需要充分可比的口径；未经核对的差额不能命名为准确自然销量，也不能证明广告新增的销量。

## 六 从小范围验证走向可复用流程

### 三个优先场景

| 场景 | 最小可行输出 | 验证办法 |
|---|---|---|
| 销售日报 | 单站点、完整日期的销售与销量汇总 | 与后台同口径核对，记录更新时间 |
| 商品搜索诊断 | 曝光到购买各环节的异常商品及待查原因 | 用完整可比周期，一次验证一个主要变量 |
| 促销利润复盘 | 活动销售、折扣、费用、广告及成本的对应关系 | 比较可比基线或对照，避免把全部活动销售当增量 |

库存与订单巡检可在上述流程上继续接入，但应分别验证权限、分页与字段含义。高 ACoS、余额减少或单日销量下降，都不足以单独决定关广告、判断冻结或大量补货。

### 一个流程的验收顺序

先确认目标和权限，再对齐数据口径；先校验流程定义，再运行小范围查询；最后确认文件可用、结果与后台一致，并记录失败情况。提交查询不要盲目重复重试，已有查询应支持继续处理。

长期运行还需要调度器、持续可用的运行环境、限流控制、失败恢复、日志和人工处理。单次成功不等于每日自动运行；AI 生成迁移建议也不等于代码已经编译测试通过。

### 可复制的提问方式

请先核对我有权限的站点、所需字段、币种、时区和完整日期。创建一个销售汇总工作流，包含有限次数等待、状态分支、文件下载、解析和日志；已有查询时支持继续处理。运行后与卖家中心同口径核对。将已确认事实、合理假设、待核实信息分开，最多给出三个下一步建议。不要把凭证、原始经营数据或临时签名下载链接写入共享资料。

### 共享与操作边界

对外包保留公开资料、技术结论和会议照片，未附带测试账号、密钥、原始响应、后台截图、运行标识或真实工作流输入。会议照片本身包含现场观众和演示画面，属于本次会场材料。

sp_api_execute 和工作流能够触发写操作，不是天然只读。生产使用应落实程序侧接口白名单、权限隔离和写入校验，不能仅依赖提示词。会场安全政策的具体期限与例外应回正式文件核对，照片摘要不能替代完整条款。
