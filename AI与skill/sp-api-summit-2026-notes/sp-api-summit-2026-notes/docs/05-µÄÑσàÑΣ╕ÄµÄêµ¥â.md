# 5 接入与授权

## 5.1 本地 MCP 不是一个公网网址

npm 是软件安装渠道。这个 MCP 在**本机启动**，通过 stdio（标准输入输出）与 AI 客户端通信，再通过 HTTPS 请求亚马逊。因此无需先申请公网 MCP 地址。本地运行仍需联网；数据进入 AI 客户端后如何处理，取决于所用平台及设置。

以下为本批测试使用的固定版本示例，不表示该版本永远最新。运行环境为 Node.js 20 或以上。

```bash
npm install -g @amazon-sp-api-release/sp-api-dev-mcp@1.0.5

# 开发助手
sp-api-dev-assistant-mcp-server

# 工作流服务器
sp-api-workflow-mcp-server
```

也可以不全局安装，直接在 MCP 客户端里用 `npx -y` 调起；完整客户端配置示例见 4.8。

## 5.2 环境变量（仅列含义，不附真实凭证）

| 配置 | 用途 |
|---|---|
| `SP_API_CLIENT_ID` | 应用客户端编号 |
| `SP_API_CLIENT_SECRET` | 对应应用密钥 |
| `SP_API_REFRESH_TOKEN` | 卖家授予该应用的长期授权凭证 |
| `SP_API_REGION` | 按实际区域选 na、eu 或 fe |
| `SP_API_BASE_URL` | 对应区域的公开 API 地址 |

**`NPM_TOKEN` 属于发布软件包到 npm 的流程**，普通用户安装公开包不需要申请；它不是店铺授权令牌。

## 5.3 应用编号和令牌不要混用

| 概念 | 作用 |
|---|---|
| Application ID | 标识 SP-API 应用 |
| Client ID / Client Secret | 识别 OAuth 客户端 |
| Refresh Token | 特定卖家给该客户端的授权 |
| Access Token | 调用时使用的短期令牌 |

**LWA（Login with Amazon）** 是亚马逊的授权实现。建立安全配置文件不会自动获得卖家业务权限，刷新令牌也不能跨客户端混用。测试中曾出现 `unauthorized_client`，更换为对应应用凭证后成功换取访问令牌；**单看错误码不能判定所有同类失败都出于同一个原因。**

## 5.4 自授权和公共应用授权

| 方式 | 适合场景 | 关键步骤 |
|---|---|---|
| 自授权 | 自己有资格授权的账号进行接入测试 | 在应用管理中授权，安全保存刷新令牌 |
| 公共应用 OAuth | 让其他卖家接入自己的应用 | 注册登录与回调地址，验证 state，及时兑换授权码，按卖家隔离令牌和数据 |

公共应用可用自授权测试；但**自授权成功不等于网站回调已通过验证**。其他卖家不需要获得开发者的 Client Secret。回调网址背后必须有处理程序，仅填一个地址不构成完整授权服务。

刷新令牌是长期、可撤销的凭证；公共应用还涉及定期重新授权要求，不能承诺永久有效。自动换取 Access Token 也不等于可以自动恢复已撤销的卖家授权。

参考：[自授权](https://developer-docs.amazon/sp-api/docs/self-authorization)（当前页面标题为 Authorize Private Applications）· [公共应用授权](https://developer-docs.amazon/sp-api/docs/authorize-public-applications) · [重新授权](https://developer-docs.amazon/sp-api/docs/renew-authorizations)

## 5.5 身份与权限辨别

| 概念 | 白话解释 | 如何确认 |
|---|---|---|
| Seller 第三方卖家 | 通过平台向消费者销售 | Seller Central 后台及卖家业务授权 |
| Vendor 供应商 | 向亚马逊供货，由亚马逊零售 | Vendor Central 供应商合同和采购订单 |
| SPN 服务商网络 | 面向卖家提供服务的机构网络 | 服务商申请及审核，不是商品销售身份 |
| Brand Registry 品牌注册 | 品牌相关资格体系 | 品牌后台及关联角色 |
| SP-API Role 应用角色 | 软件可访问哪些业务资源 | 开发者资料、应用配置及重新授权情况 |

- 使用 FBA 不会把 Seller 变为 Vendor；公司可能同时有卖家与供应商业务，确认其中一个账户类型不能排除另有另一类账户。
- **品牌分析可读不能证明操作人是品牌所有者或管理员。**
- 角色不是唯一身份标签，一个应用可以拥有多项权限。
- **读取报表列表返回 200，不足以证明可以生成任意报表**；列表为空既不能证明没权限，也不能证明没有业务。
- 新增角色可能需要开发者审核、更新应用并重新授权。

参考：[SP-API 角色定义](https://developer-docs.amazon/sp-api/docs/roles-in-the-selling-partner-api) · [接口角色权限对照表](https://developer-docs.amazon/sp-api/lang-zh_CN/docs/role-mappings) · [Seller Central 与 Vendor Central 区别](https://sell.amazon.com/tools/seller-central)
