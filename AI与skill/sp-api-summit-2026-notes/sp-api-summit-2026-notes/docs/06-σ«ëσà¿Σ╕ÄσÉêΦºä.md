# 6 安全与合规

> 以下为会场对解决方案提供商的安全要求介绍。**具体适用主体、例外条款、政策全文与生效条件没有在照片中完整呈现，实施时应补齐正式文件**【待核实 Q11–Q13】。

## 6.1 数据保护与加密【现场 IMG_2395】

| 主题 | 照片记录 |
|---|---|
| 传输 | TLS 1.2 及以上 |
| 静态数据 | 最低加密要求写为 AES-128 或 RSA-2048 |
| 密钥 | 管理密钥全生命周期，仅限自有程序和服务访问 |
| 删除 | 四类触发条件任一发生即开始计时，30 天内完成删除；四类条件未在图中展开 |
| PII | 商品送达完成后 30 天内删除 |
| 数据擦除 | 遵循 NIST 800-88 等标准 |
| 销毁证明 | 应 Amazon 要求提供认证证明 |
| 实践 | 覆盖公共网络、跨网络边界与第三方交互；非可信环境端到端加密；独立数据库或来源标签；自动化删除 |

**【解读】** 把敏感数据接进 ERP 后，还要知道数据在哪里、谁能看、什么时候应删除。照片中的"30 天"不是对所有经营数据统一保留 30 天的结论，也不能脱离完整政策解释例外。

## 6.2 漏洞扫描与渗透测试【现场 IMG_2396】

- 至少每 **30 天**开展一次全量扫描
- 重大变更后立即重新扫描
- 每次软件发布前执行代码扫描
- 每 **365 天**开展一次全面渗透测试
- 严重漏洞 **7 天**内闭环，高风险漏洞 **30 天**内闭环
- 覆盖网络、云端、应用、API 和存储；采用认可的方法，集成自动扫描，保存扫描与修复记录

**漏洞扫描**是查找潜在弱点；**渗透测试**是在约定范围内模拟攻击，验证弱点能否被实际利用。照片没有给出风险分级标准与计时起点，需补正式规则后再制作企业执行表。

## 6.3 身份、认证与访问控制【现场 IMG_2397】

标题提示："授权要窄、复核要勤、回收要快"。

| 项目 | 会场表述 |
|---|---|
| 登录保护 | 所有用户账户启用多因素认证 |
| 身份 | 每位用户分配唯一身份标识 |
| 权限 | 最小权限，默认拒绝访问 |
| 服务账户 | 登记明确责任人 |
| 账户锁定 | 连续 10 次验证失败即锁定 |
| 密码 | 不少于 12 位字符；最近 10 次密码禁止复用 |
| 闲置访问密钥 | 满 90 天无成功调用即由亚马逊删除 |

最后一项的密钥类别及执行范围照片没有完整说明，**不要据此对所有云平台密钥作相同推断**【待核实 Q12】。

## 6.4 安全合规自查评估【现场 IMG_2398】

已同步 2026 年 8 月政策变更；支持多语言；包含 30 多道解决方案提供商政策是非题；免费匿名参与并即时生成整改得分报告。

**记录边界：** 照片能证明会场提供了这个自查入口，**不能证明已参加、通过评估或取得合规认证**。本次没有提交自查表。

## 6.5 AI 场景下的写操作边界

`sp_api_execute` 和工作流**能够触发写操作，不是天然只读**。生产使用应落实程序侧接口白名单、权限隔离和写入校验，**不能仅依赖提示词**。会场安全政策的具体期限与例外应回正式文件核对，照片摘要不能替代完整条款。

**共享边界：** 对外分享保留公开资料、技术结论和会议照片，未附带测试账号、密钥、原始响应、后台截图、运行标识或真实工作流输入。
