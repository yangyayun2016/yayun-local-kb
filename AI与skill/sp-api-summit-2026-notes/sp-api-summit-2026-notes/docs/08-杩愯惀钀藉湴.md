# 8 运营落地

## 8.1 把数据对应到五个业务问题

| 问题 | 主要数据 | 还要补什么 |
|---|---|---|
| 店铺有没有风险 | 商品问题、订单与履约异常 | 账户绩效、政策通知、工单和退货详情 |
| 卖得怎么样 | 订单、销量、销售额、流量（会话、浏览） | 完整日期、订单状态、前日与上周同日基线、退款口径 |
| 赚不赚钱 | 交易、费用、退款、净销售 | 采购、头程、包装、汇率、税务及外部成本分摊 |
| 广告有没有浪费 | Ads API 花费与归因销售，结合整体销售 | 商品利润、归因窗口、投放目的与搜索词 |
| 库存是否安全 | 可配送、预留、不可售及在途库存 | 销量、补货周期和到货可靠性 |

> 本汇编没有读取任何店铺数据，因此没有得出"广告浪费""断货"或"利润下降"等店铺诊断结论。

## 8.2 三个优先场景

| 场景 | 最小可行输出 | 验证办法 |
|---|---|---|
| 销售日报 | 单站点、完整日期的销售与销量汇总 | 与后台同口径核对，记录更新时间 |
| 商品搜索诊断 | 曝光到购买各环节的异常商品及待查原因 | 用完整可比周期，一次验证一个主要变量 |
| 促销利润复盘 | 活动销售、折扣、费用、广告及成本的对应关系 | 比较可比基线或对照，避免把全部活动销售当增量 |

库存与订单巡检可在上述流程上继续接入，但应分别验证权限、分页与字段含义。**高 ACoS、余额减少或单日销量下降，都不足以单独决定关广告、判断冻结或大量补货。**

## 8.3 统一分析表的拼表顺序

1. 先固定账号、商城、币种、站点时区、完整日期与数据更新时间。
2. 商品级表按**账号＋商城＋日期＋子 ASIN** 汇总；若用 SKU，先确认 SKU 与 ASIN 映射是否一对一。
3. 广告活动／广告组先聚合到同一商品日期粒度，再关联整体销售；否则多个活动会把同一商品的总销售额**重复计算**。
4. 保留稳定的活动和广告组 ID，名称主要用于展示。
5. 同时保存广告归因窗口和字段定义，区分订单数、销量件数、订购销售额、净销售额与广告归因销售额。
6. 检查缺失、重复、分母为零与广告归因回补，再计算比率；**不能把空值一律当零**。

## 8.4 一个流程的验收顺序

先确认目标和权限 → 对齐数据口径 → 校验流程定义 → 运行小范围查询 → 确认文件可用、结果与后台一致 → 记录失败情况。

提交查询不要盲目重复重试，已有查询应支持继续处理。长期运行还需要调度器、持续可用的运行环境、限流控制、失败恢复、日志和人工处理。**单次成功不等于每日自动运行；AI 生成迁移建议也不等于代码已经编译测试通过。**

## 8.5 三个学习卡（新人可直接照做）

### 卡 A：企业购标签核对

- **场景：** 企业客户反馈包裹难以对应采购单
- **步骤：** 确认企业购订单 → 核对 PO 字段 → 核对收货公司 → 比对 ERP 展示 → 比对承运人标签
- **判断标准：** 原始订单、ERP、标签上的关键内容一致；缺失项明确提示；字段太长不会悄悄截断
- **常见错误：** 只有公司名称没有 PO；订单已更新但标签仍用旧缓存；把现场示例当成所有承运人通用字段

### 卡 B：促销巡检

- **场景：** 活动建好了，但部分商品没有出现预期优惠
- **步骤：** 搜索活动 → 看完整活动状态 → 查询全部商品选择页 → 找到商品级问题 → 回后台核对商品资格与买家端展示
- **判断标准：** 活动 ID、站点、起止时间、商品范围、优惠条件一致；能解释是活动层还是商品层问题
- **常见错误：** 只查第一页；把活动正常当成所有商品正常；把满减直接扣到每件商品上；把能查询误认为能修改

### 卡 C：整体销售与广告拼表

- **场景：** 想判断销量变化与广告投入是否有关
- **步骤：** 定账号／站点／完整日期／币种 → 定子 ASIN 或 SKU 粒度 → 先汇总广告 → 关联整体销售 → 查重复与缺失 → 计算指标 → 写证据与待验证原因
- **判断标准：** 关联前后整体销售总额不被放大；各字段单位清楚；广告窗口和数据更新时间可见；分母为零不输出误导比例
- **常见错误：** 把 `sales7d` 当作全部销售；订单数当件数；把所有活动行上的整体销售加总；当天未完整数据与完整日直接比较

## 8.6 三道判断题

**题 1｜自然销量能不能直接相减？** 某天总销量 100 件，广告报表 `orders7d` 为 30，能否得出自然销量 70 件？

> **不能。** 总销量是件数，`orders7d` 是订单数，而且日期、归因窗口、商品归属仍可能不同。先找同口径的广告件数字段并确认归因逻辑；无法对齐时，不输出精确自然销量。

**题 2｜这件商品现在便宜了多少？** 某商品标价 14.79 美元，提示"选定商品满 30 美元减 5 美元"，能否记成成交价 9.79 美元？

> **不能。** 优惠有门槛和适用商品条件，还需确定订单如何满足条件、优惠如何分摊。记录原价、促销形式、门槛与适用范围，比强行写一个无条件折后价更准确。

**题 3｜AI 已经把迁移做完了吗？** AI 列出四个 Java 文件的 Critical 问题并给出修改方向，是否表示迁移完成？

> **不表示。** 照片证明的是分析过程。还需确认正式目标版本、实施修改、编译、测试订单创建／取消／追踪、处理失败和回滚。本次资料里正式演讲页与演示目标版本还不同。

## 8.7 可复用的 AI 提示词

**提示词一｜创建并验收一个数据工作流**

```text
请先核对我有权限的站点、所需字段、币种、时区和完整日期。
创建一个销售汇总工作流，包含有限次数等待、状态分支、文件下载、解析和日志；已有查询时支持继续处理。
运行后与卖家中心同口径核对。
将已确认事实、合理假设、待核实信息分开，最多给出三个下一步建议。
不要把凭证、原始经营数据或临时签名下载链接写入共享资料。
```

**提示词二｜分析单个商品的经营表现**

```text
请根据我提供的店铺报表分析一个商品。
先核对账号、站点、币种、时区、日期是否完整，区分订单数与销量件数、整体销售与广告归因销售。
广告归因窗口不一致时，先说明哪些指标不能直接相减或比较。
按店铺风险、销售、广告、库存、今日行动的顺序组织。
每个结论标注证据，区分已确认事实、合理假设、待验证信息。
最多给出三个优先动作，每个都写今天怎么做、下一次怎么验证。
没有的数据明确写缺失，不从会议示例中补造店铺数据。
```

## 8.8 真实店铺练习记录模板

```text
日期／站点／币种／时区：
商品与账号范围：
数据来源与更新时间：
广告归因窗口：
已确认异常：
可能影响：
合理假设（不要写成已确认原因）：
还要查什么：
今天要做什么：
明天／归因稳定后如何验证：
结果与下一步：
```

## 8.9 三个优先学习动作

| 优先动作 | 当前缺口 | 具体操作 | 下一次验证 |
|---|---|---|---|
| 补齐会议原始资料 | 财务场缺正文，问答无答案，版本关系未解释 | 优先补财务手册、官方 PPT、发布与迁移说明 | 待核实项是否有原始证据支持并关闭 |
| 做一张商品日级数据口径表 | 整体销售与广告数据混用会误判 | 选一个站点、一个商品、一个完整周期，先定义字段与单位，再考虑取数 | 总销售是否重复、订单与件数是否分开、币种与归因窗口是否标注 |
| 做一个读取演示的小验证 | 截图证明演示存在，不证明自己的环境已可用 | 有权限后，从订单读取或商品状态查询中选一项，核对后台与返回字段 | 记录成功／失败、缺字段、更新时间及与后台的差异 |
