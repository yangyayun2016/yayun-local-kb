## 1.3 三条主线

1. **接口把订单、商品、履约和经营数据连接起来。**
2. **AI 与 MCP 帮开发者理解、调用和迁移接口。**
3. **运营分析需要把店铺整体表现与广告表现放在一起看。**

对运营新人，最有价值的不是背接口名称，而是知道 ERP 能解决哪些问题、数据是否完整，以及可以向技术人员提出什么具体需求。

## 1.4 最需要保留的四个判断

1. **读取能力与写入能力分开看。** 促销读取已发布的现场口径，不等于创建更新也已开放。
2. **AI 输出要回到版本与测试。** 迁移演示有明确的预发布提示，与另一页版本不同，不能直接上线照用。
3. **数据连接要先统一口径。** 站点、时间、币种、粒度和归因窗口对不上，漂亮的统一看板也可能误导运营。
4. **API 接入包含持续维护。** 同步、分页、错误处理、权限、删除与测试，都是软件可用性的一部分。

## 1.5 核心结论

现有测试记录已覆盖官方 MCP 安装与库存读取、部分订单与财务查询，以及一次 Data Kiosk 销售汇总工作流和后台对账。它们证明了**具体链路可以跑通**；完整利润、广告优化和长期自动化仍需要更多数据、权限与运行保障。
