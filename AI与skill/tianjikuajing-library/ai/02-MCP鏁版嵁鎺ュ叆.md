# 02 MCP 数据接入

## 要解决什么问题

让 AI 能直接读取你已有的数据工具，而不是手工复制粘贴。

## 准备什么

- 数据工具账号与 API 或 MCP 访问权限（如卖家精灵、SIF、Sorftime 等，以各工具官方文档为准）
- 支持自定义连接器或 MCP 的 AI 客户端
- 一个存放密钥的安全位置（不是代码仓库）

## 一步步怎么做

### Step 1：理解 MCP 的角色

MCP（Model Context Protocol）是让 AI 调用外部工具和数据的标准接口。工具方提供 MCP 服务，AI 通过它查询、分析、返回结构化结果。

### Step 2：接入顺序

1. 从**只读**工具开始（选品数据、关键词数据、竞品数据）
2. 在 AI 客户端的连接器设置里添加工具方提供的服务地址并完成授权
3. 用一个真实 ASIN 或关键词做测试，核对返回数据与工具网页是否一致
4. 再考虑接入自有系统（广告、订单）

### Step 3：官方 API 优先

对亚马逊自身数据，优先使用官方接口（如 Selling Partner API、Amazon Ads API），并遵守其使用政策。不建议用模拟网页操作的方式做批量写入，存在账号风险。

### Step 4：安全纪律

- 密钥与令牌**绝不提交到 GitHub**；使用环境变量或密钥管理工具
- 给 AI 的权限按最小化原则授予：能只读就不给写
- 所有写操作先输出「将要做什么」，人工确认后再执行
- 敏感经营数据（成本、利润、供应商）不要放进公开仓库

### Step 5：数据口径校验

接入后，对每个核心指标做一次交叉验证（工具数据 vs 后台数据），记录误差范围。第三方工具的销量和流量多为估算值，使用时要注明。

## 常见坑

- 以为第三方估算值就是真实值。
- 把密钥写进配置文件并提交。
- 让 AI 直接批量改广告而没有人审。

## 完成检查清单

- [ ] 至少一个只读数据源已接入并校验
- [ ] 密钥不在仓库里
- [ ] 写操作有人工确认环节
- [ ] 数据误差范围已记录
