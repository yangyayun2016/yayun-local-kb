# 04 提示词与质检

## 要解决什么问题

有一组可直接复用的提示词，也有一份输出质检清单，避免 AI 的「看起来对」。

## 准备什么

- 已整理好的输入数据（表格、评论、搜索词报告等）
- 明确的输出格式要求

## 一步步怎么做

### Step 1：提示词库

每条提示词都应写明：**角色、输入、输出格式、禁止事项**。

| 场景 | 必需输入 | 输出 |
|---|---|---|
| 竞品拆解 | 竞品 ASIN 数据、评论、价格变化 | 定位、卖点、弱点、可借鉴点 |
| 评论洞察 | 近期评论文本 | 好评与差评主题、占比、可行动建议 |
| 德语 Listing 起草 | 产品信息、关键词、卖点 | 标题、五点、描述草稿（需母语审校） |
| 广告周报解读 | 搜索词报告、花费与订单 | 否词、扩词、调价建议清单 |
| 搜索词归类 | 搜索词列表、产品信息 | 标签（核心 / 长尾 / 竞品 / 无关）与理由 |
| 采购沟通 | 报价与需求 | 邮件草稿，含问题清单 |
| VC 异常邮件 | PO 与差异信息 | 简洁、客观的说明草稿 |
| 合规清单核对 | 产品类别与市场 | 需核对的项目清单（非结论） |
| 日报生成 | 当日数据 | 一页摘要：异常、动作、待办 |
| 复盘 | 一次动作的时间线与结果 | 做对、做错、可复用 SOP |

### Step 2：通用提示词骨架

```
你是一名熟悉亚马逊<站点>的运营分析师。
输入：<粘贴数据，并说明字段含义>
任务：<具体要做什么>
输出：<表格或清单，列出字段>
要求：
1. 缺少数据时列出缺口，不要编造数字
2. 所有假设值标注"工程假设"
3. 每个结论给出依据（引用输入中的哪些数据）
```

### Step 3：输出质检清单

- [ ] 数字是否可以回溯到输入数据
- [ ] 计算是否由脚本或表格复核
- [ ] 是否出现了没有来源的绝对化宣称（如「最好」「第一」「保证」）
- [ ] 是否涉及医疗、安全、法规类断言（需要专业复核）
- [ ] 外语内容是否经过母语或熟悉市场的人审校
- [ ] 是否包含不应公开的成本、供应商、账号信息

## 常见坑

- 提示词没有格式要求，输出难以复用。
- 让 AI 做合规「结论」。
- 复制粘贴 AI 文案，没有校验事实。

## 完成检查清单

- [ ] 至少 3 条提示词已按骨架整理
- [ ] 质检清单已贴在手边
- [ ] 外发内容有人审环节
