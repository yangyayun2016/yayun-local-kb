# 02 需求与竞争评估

## 要解决什么问题

判断这个市场的需求是真的、稳定的，并且一个新品还有机会切进去。

## 准备什么

- 候选品的核心关键词（3–10 个）
- 一个以上的数据工具；如已品牌备案，使用 ABA
- 近 12 个月的搜索趋势与榜单变化

## 一步步怎么做

### Step 1：验证需求是真的

- 至少用**两个独立数据源**交叉验证搜索需求（如 ABA 搜索频次排名 + 第三方工具估算 + Google Trends）。
- 看 12–24 个月趋势：是稳定、增长、衰退，还是只在某个节日脉冲。
- 看需求是否集中在一个精确词，还是分散在大量长尾词里（影响广告结构与流量天花板）。

### Step 2：评估竞争强度

| 维度 | 看什么 | 解读 |
|---|---|---|
| 头部集中度 | ABA 中前三 ASIN 的点击份额、转化份额 | 份额极度集中，新品很难进入 |
| 评论门槛 | 首页链接的评论数、评分分布 | 门槛高，需更强的差异化或更长的积累期 |
| 新品窗口 | 近 12 个月上架且月销达标的链接占首页的比例 | 比例越高，说明市场对新品开放 |
| 广告强度 | 核心词建议出价 ÷ 客单价 | 出价占客单价比例过高，利润被广告吞掉 |
| 价格带 | 价格分布与价格战迹象 | 价格带塌陷意味着利润空间在缩小 |
| 品牌占比 | 首页品牌是否集中在少数大牌 | 大牌占主导则需要避开正面竞争 |

### Step 3：用评分卡收口

给每个维度打 1–5 分，加权汇总。权重需要明确标注为 `【工程假设】`，并写进配置文件，方便复盘时调整，而不是藏在脑子里。

```json
{
  "demand": { "weight": 0.30, "engineering_assumption": true },
  "competition": { "weight": 0.30, "engineering_assumption": true },
  "profit": { "weight": 0.25, "engineering_assumption": true },
  "differentiation": { "weight": 0.15, "engineering_assumption": true }
}
```

合规一项不参与加权，**直接一票否决**，见 [03](03-利润测算与风险排查.md)。

### Step 5：做差评与问答分析

读首页竞品的低星评论和 Q&A，归纳 3–5 个高频痛点，作为差异化的输入。这一步非常适合用 [AI 篇](../ai/README.md) 的评论洞察提示词批量完成。

## 常见坑

- 只看某一周的数据，被促销或节日误导。
- 把第三方工具的销量估算当作真实销量。
- 只关注精确词，忽略类目整体需求边界。

## 完成检查清单

- [ ] 需求已用至少两个数据源验证
- [ ] 已看 12–24 个月趋势和季节性
- [ ] 竞争六维都有记录
- [ ] 评分卡的权重已标注为工程假设
- [ ] 已归纳 3–5 个竞品痛点
