方式上的改变
04

之前的做法：
工作量大，只能先分析一个角度 → 在 Excel 里手动整（加公式、做透视）→ 过一遍也懒得写报告
问题在于：非常依赖个人经验
我自己做费时费力，教给运营做，结果不一定是我要的，还得反复改

Skill 的做法：
把分析角度写成 Skill → 数据导出给 AI → AI 按预设逻辑执行 → 标准化报告
好处：角度齐全（就算某个维度暂时不用，也能快速过一眼）
可以复制给整个团队用、后面还能迭代补新角度

怎么做？
05

我自己现在用 Cursor + Claude Code 写这些 Skill（原因是写出来的质量相对高，也能读更多本地文件）
但老实讲， 小白我更建议先用 Coze 上手 ：技能商店 → 创建技能（门槛更低，适合先搭一两个感受下变化）

第一步：选一个你最擅长的
先别碰最复杂的，挑一个你闭着眼都能分析的那份报告

第二步：把你的分析步骤写下来
把 AI 当成一个很聪明、但不懂亚马逊的实习生，告诉它你的分析角度
不需要多复杂的提示词，比如：「出现 men 或 women 就打标成人群词」

第三步：让 AI 跑一遍，直接看结果
把数据和你刚搭的 Skill 一起丢给 AI，跑完看输出
一定会有那些「我以为很明显但 AI 没理解」的地方
——补几句说明就行（在 Coze 里就是「技能改造」）

第四步：迭代 2～3 次
每次跑完看结果，缺的补上、多余的删掉
熟悉之后可以翻翻 skill.md 看具体怎么写
2～3 次之后，你就有一个用起来很称手的 Skill

为什么说是「最应该掌握」
06

门槛低
用自然语言跟 AI 对话就行，不需要懂 API、不需要会 Python
价值高
过去分析一份报告，再熟也要半小时。拿半小时对话整理成 Skill 之后，后面再分析，五分钟搞定。投入产出比没得说
顺带练结构化表达
最近用 AI 多了，感觉除了「会提好问题」， 结构化表达 也越来越重要
多轮对话下来，看看写好的 skill.md，能很快学到怎么有逻辑、有结构地跟 AI 对话
AI 时代的「SOP」
传统 SOP 写在文档里，靠人执行，质量参差不齐
Skill 写在 AI 里，AI 执行， 每次输出质量一致 
这才是真正的标准化
