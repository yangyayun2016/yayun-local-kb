# LT 广告架构参考

当用户要求广告架构、流量层、预算转移、缺失流量、冗余流量、混层、空壳广告组或 campaign/ad group 健康诊断时，使用本参考。

## 核心原则

广告架构不是只判断单个广告组好坏，而是回答：

- 哪些流量层应该存在？
- 哪些流量缺失、承接不足或混在一起？
- 哪些层浪费预算、重复承接或是空壳？
- 预算应从哪里释放、转到哪里？

先做 LT 分层，再判断表现和动作。

## 操作链路

```text
原始报表 / ASIN Center adTree
-> 归一化 campaign、ad_group、targeting、search_term、ASIN/SKU、metrics
-> 映射 LT 流量层
-> 按 LT 层聚合表现
-> 对比应有架构
-> 判断缺失、承接不足、多余、混层、空壳、可转移、健康
-> 输出补层、拆层、清层、转移预算、保护、暂停、观察
```

## 默认 LT 层级

| LT层级 | 架构目的 | 常见信号 |
|---|---|---|
| 品牌防守层 | 保护品牌和高确定性流量 | 自有品牌词、品牌 campaign、brand phrase/exact |
| 核心Exact收割层 | 承接已验证高转化核心词 | exact match、有订单、ACOS/ROAS 健康 |
| 品类Phrase扩展层 | 受控拓展相关类目词 | phrase match、类目词、核心词修饰 |
| Broad探索层 | 发现未来可收割的新词 | broad match、broad 命名、探索活动 |
| 竞品抢夺层 | 抢竞品品牌或竞品 ASIN 流量 | 竞品词、竞品 ASIN、conquest 命名 |
| ASIN/商品定向层 | 商品详情页和 ASIN 定向 | target ASIN、product targeting、expression |
| Auto探索层 | 低门槛发现边缘查询 | auto、close match、loose match、substitutes、complements |
| 空壳/边缘层 | 低价值或残留流量 | 低花费、低证据、角色不清、长期无转化 |

如果一个 campaign/ad group 混入多个层级，标记为“混层”。混层即使 ACOS 暂时不错，也可能需要拆层或清词。

## 层级状态

- `符合架构`：角色清楚，表现支持保留。
- `缺失`：应有层级没有明确 campaign/ad group/targeting 承接。
- `承接不足`：层级存在，但无法承接足够流量、exact 收割或转化。
- `多余`：层级重复承接，或与当前策略不匹配地消耗预算。
- `混层`：品牌、核心、品类、竞品、auto 等流量混在一个组里。
- `空壳`：活动/广告组存在，但几乎没有有用流量或证据。
- `可转移`：弱层、空壳或多余层的预算可以转给强层或缺失层。
- `需观察`：数据量不足，不适合做高影响动作。

## LT 归因表

架构类输出先给这张表：

```text
LT层级 | 架构目的 | 当前承接组 | 花费 | ACOS/ROAS | 层级状态 | 归因结论 | 治理动作
```

字段规则：

- `当前承接组` 写 campaign/ad group/targeting，不要只写“有”或“无”。
- `花费` 和 `ACOS/ROAS` 尽量按层聚合；无法聚合时说明原因。
- `归因结论` 用一句话说清缺失、冗余、混层、空壳或健康。
- `治理动作` 使用补层、拆层、清层、转移预算、保护、暂停、观察。

## 判断顺序

1. 应有 LT 层级是否齐全？
2. 哪些层缺失或承接不足？
3. 哪些层重复承接或不该花钱？
4. 哪些 campaign/ad group 是空壳，可以释放预算？
5. 哪些组混层，需要拆分或清词？
6. 哪些层符合架构且表现健康，需要保护？
7. 预算或流量应从哪里转移到哪里，证据是什么？

不要让用户从一堆 ad group 行里自己推断架构问题。

## 防线

- 不说“广告组健康”而不说明它属于哪一层。
- 不把好 ACOS 等同于好架构；混层仍可能需要治理。
- 不把所有低花费组都判定为无用；低样本默认观察，除非角色明显错误。
- 不从 LT 架构单独推断 Listing、价格、评论、库存或利润根因。
- 暂停、否定、预算转移、明显提 bid 都需要人工确认。
