# TRACE 质量自检清单

本文件用于检查 Skill 本身或最终选品输出是否满足用户整理的五原则 TRACE。

## T - Trust 信任

检查点：

- 不包含可疑代码注入、敏感信息泄露或不必要的外部依赖。
- 支持中文交互和中文输出。
- 能在没有海外 API 的情况下基于用户提供的数据、卖家精灵结果或手动观察继续分析。
- 对专利、合规、安全、平台限制等风险保持明确提示。

## R - Reliability 可靠性

检查点：

- 对同类输入有稳定流程：输入确认、单品拆解、机会拓展、市场验证、候选评分、下一步建议。
- 对数据缺失、格式不标准、输入过短、输入过长等情况给出友好提示或合理假设。
- 不因为缺少某个指标就中断，而是标记为“待验证”并说明补数方式。
- 输出结构固定，便于复用和比较。

## A - Adaptability 适用性

检查点：

- 触发场景清晰：亚马逊选品、拓品、单品到品类、卖家精灵 AI-拓产品结果解读、细分/互补机会筛选。
- 能力边界清晰：负责发现和验证方向，不替代最终商业决策。
- 不应触发的场景：泛泛的财务分析、非电商产品设计、无关行业研究、需要真实法律结论的专利/合规判断。

## C - Convention 规范性

检查点：

- 技能包包含必需的 `SKILL.md`。
- 可选资料放入 `references/`，并在 `SKILL.md` 中说明何时读取。
- `SKILL.md` 只保留核心流程，不堆叠所有长篇资料。
- 命名使用小写字母、数字和连字符。
- 有输入输出示例、执行流程和 Guardrails。

## E - Effectiveness 有效性

检查点：

- 输出不只是方向清单，而是产品机会地图。
- 能解释每个方向属于细分赛道、互补赛道还是组合机会。
- 能把 50 个方向收敛为 5 个候选，再推荐 1-2 个优先验证方向。
- 能把数据、痛点、供应链、利润、合规和公司阶段放在同一张判断框架里。
- 最终交付能直接进入下一步验证，而不是需要用户重新整理。

## 最终自检问题

- 用着放心吗？
- 每次都稳吗？
- 该出手时出得来吗？
- 写得清楚、改得动吗？
- 最终交付的结果好用吗？
