# 天哥·复刻术 · 引擎手册（AGENTS.md）

你（Codex）在这个目录里就是一台**爆款视频复刻引擎**，对应 skill **`天哥复刻`（`/tiange_fuke`，定义见 `tiange_fuke.md`）**。
用户**扔进一条爆款视频 + 一句话**，你的职责是**全自动**把它复刻成「骨架神似、画面全新」的新片，
并产出「上=复刻 / 下=原片」的上下屏对比片。
**零人工的前提是宿主有视觉能力**（如 Codex）：你自己看关键帧写分镜、自己出片。
headless / 无视觉宿主下，第②步（看帧填 storyboard 分镜）需要人工完成，其余全自动。

## 一句话方法论
**复刻 = 先抓「爆点」+ 锁死「骨架」+ 替换「血肉」。**
- 🔥 **爆点（第 0 步，最重要）**：这视频**为什么火**？那个让人想看第二遍的瞬间是什么？
  换装 / 转场 / 人和衣服一起转 / 前后反差 / 卡点……**爆点本身就是骨架的核心**，必须 1:1 复刻，
  绝不能当成可简化的细节。**抓不住爆点，切点时长全对了也是废片。**
- 骨架（必须 1:1）：分镜切点、各段时长比例、运镜节奏、关键视觉冲击点、转场。
- 血肉（全部替换）：主体（产品/人物）、环境、配色、卖点文案语言。
- 这类带货爆款靠「真实质感建立信任→转化」，**质感比画质更重要**。

## ⚠ 上一版踩的坑（必看，别重犯）
复刻「阿狗陶陶低电量穿搭」时，爆点是**换装 + 转身 + 人和衣服一起转**，
但产出做成了**静态白底穿搭清单棚拍**——切点/时长 1:1 对上了，**爆点全丢了，人根本没转**。
两个根因，现在都已在引擎里堵上：
1. **没人先问「为什么火」**：爆点没被显式写下来 → agent 默认选了最安全的静态解释。
   → 现在 `storyboard.json` 顶部强制有 `爆款点` 字段，没填满 `shots.py` 直接拦下不让生成。
2. **agent 没『看见』运动**：每镜只抽 1 张中点帧，看不出她在转 → 写不出转的 prompt。
   → 现在每镜抽 **首/中/尾 3 帧**（`g*_a/_b/_c.jpg`），对比就能看出转身/换装。
   → 且换装类视频多用「转身」做无缝转场、没有硬切点，`auto_storyboard` 会**按时间均匀切**兜底并告警。
**Seedance 是首帧锁定型**：首帧什么姿势就保持什么姿势，**不在 prompt 里写死动作，它就不会动**。
爆点是动作（转身/换装）时，每镜 prompt 必须把动作写满，否则护栏会拦你。

## 工具分工（关键约定）
- **拆骨架 / 抽关键帧 / 拼接 → `pipeline/`（ffmpeg）。** 已脚本化，确定性的活全自动。
- **生首帧（产品/人物形象）→ 你自己内置的 `images` 生成**，存到 `_work/frames/frame_<gid>.png`。
  没有内置生图能力时（headless / 非 Codex 宿主）→ 跑 `python -m pipeline.gen_frames` 走 API 生图链。
- **生视频 → `pipeline/`（seedance 图生视频，已封装提交/轮询/退避重试）。**
- 你不亲自“画”产品文字/卖点角标——文字必乱，靠后期 ffmpeg overlay 叠真实文案（storyboard 的 `overlays`）。

## 全自动流水线（扔视频→出片，七步）
```
① 自动拆解   python -m pipeline.auto_storyboard <视频>
            → ffmpeg 拆骨架 + 合并/均匀切成生成单元(GU) + 每个 GU 抽『首/中/尾 3 帧』
            → 生成脚手架 _work/storyboard.json + 关键帧 _work/storyboard/g*_a/_b/_c.jpg
            （换装/转场类没硬切点 → 自动按时间均匀切兜底，并告警让你看帧定真正换装点）

⭐⓪ 先找爆点  【最重要，先做】把整段原片或每镜 a/b/c 三帧连起来看，回答「这视频为什么火」，
            把 storyboard.json 顶部的『爆款点』四项填满（一句话/核心机制/必须复刻的动作/千万别做成）。
            没填满或还含 TODO，shots.py 会直接拦下——这是故意的，逼你先想清爆点。

② 看帧填分镜  对比每镜 a/b/c 三帧，先写清每个 unit 的『动作』字段（有没有转身/换装/甩动）；
            判断片型(product/person) → 写 identity/scene/style/neg 全局描述
            → 给每个 unit 写 frame_prompt(首帧·英文) + prompt(运镜+动作·中文)，要叠的字填 overlays。
            ⚠ prompt 必须把『动作』写成明确指令（爆点动作尤其写满）；overlays 叠字，绝不让模型画字。
③ 生首帧     用你内置 images 按每个 unit 的 frame_prompt 生首帧 → _work/frames/frame_<gid>.png
            先生 g1 当“主形象”，其余 GU 参考 g1 保证产品/人物跨镜一致。
            （无内置生图 → python -m pipeline.gen_frames）
④ 🔴 CHECKPOINT go/no-go  只跑 g1：python -m pipeline.gen_video g1 →（python -m pipeline.preview g1 抽首/中/尾拼图）
            亲眼确认“首帧锁形象+爆点动作生效、主体不崩”。OK 再继续；不 OK 就改 g1 的 frame_prompt/prompt / 换 seed 重来。
⑤ 全量生视频 python -m pipeline.gen_video → 逐 GU 首帧锁形象+动作写进 prompt → _work/gen/clip_<gid>.mp4
            已生成的自动跳过（go/no-go 的 g1 直接复用，不重生）；崩坏只换 seed 重跑那一个 GU，不整片返工。
⑥ 拼接出片   python -m pipeline.assemble  （或第 ⑤⑥ 步一条命令跑完：python -m pipeline.run）
            → 每 GU 裁回真实时长 + 统一画幅/帧率 + concat + 叠 overlays + 自动出上下屏对比片
            → 复刻片 _work/final/<final_name>，对比片 _work/final/<compare_name>（上复刻/下原片，留原片音轨）
```

## 换装 / 转场类爆点的专门打法（这类最容易做废）
换装视频的爆点 = **「人原地转一圈，转出来衣服已经换好」的无缝转场**。两条路，二选一或叠用：
- **路线A·单镜内转换**：prompt 写死「人物正面起身 → 原地顺时针转 360° → 转身过程中服装渐变为下一套 → 转回正面已换好」，
  首帧给「正面/起转」的姿势。Seedance 能做旋转，但单镜内换装成功率中等，抽卡多试几次/换 seed。
- **路线B·靠拼接做转场（更稳，推荐）**：每个 GU 生成「这一套 + 转身到背对镜头」，下一个 GU 从「背对镜头 + 新一套」起。
  两镜都在『背对镜头那一帧』衔接 → 拼接时自然成「转身换装」的遮挡转场，比单镜内换装稳得多。
  → 写 prompt 时让相邻两镜**都经过背对镜头**，切点就藏在转最快/背对的那一帧。
- 不管哪条，**人必须跟着转**——这是爆点。做成「站定展示」就废了，护栏会拦。

## 片型判断（第②步的分叉，决定怎么写分镜）
- **产品展示型**（多角度+卖点角标，无人/有宠物）：主体=产品本体，**锁死它**——形象全程一致。
  首帧用你生成的主形象，每镜只换机位+运镜+点缀。无需换脸。
- **人物叙事型**（如减肥前后对比、身材变化类转化钩子，有人）：主体=人物，先生主角形象，同一张脸贯穿全片；
  叙事线（前/后对比）要**主动设计进 prompt**，不是照搬画面。
  客户要“指定真人换脸”是进阶路线：把 `config.py` 的 `MODEL` 切到 `doubao-seedance-2.0-fast-face`，
  生视频时把人脸图作 `reference_image` 角色喂进去（`gen_video.py` 的 `submit()` 已支持 ref_urls）。

## 验证过的铁律（别重新试错）
1. **先抓爆点再动手**：第 0 步没填满『爆款点』，shots.py 直接拦下。爆点是动作（换装/转身）时每镜 prompt 必须写动作，否则护栏拦。
2. **每镜看 3 帧才看得出运动**：只看中点 1 帧会把转身/换装误判成静态——这是上一版做废的根因。
3. **换装/转场常无硬切点**：ffmpeg 找不到切点时 auto_storyboard 按时间均匀切兜底并告警，由 agent 看帧定真正换装点。
4. **接口路径以实测为准**：第一次调用打印完整响应（APIMart 轮询是 `/v1/tasks/{id}`，无 `/status/`）。
5. **退避重试是底座不是可选**：seedance 队列常 429/503，`gen_video.py` 已内置 20 次指数退避 + 超时换 seed 重提。
6. **产品绝不让模型生成文字**：包装/卖点文字必乱码。真实产品图作首帧，或后期 overlay 叠真实文案。
7. **duration 下限 4s**：短镜头一律生成 4s，拼接阶段 ffmpeg `-t` 裁回真实时长（如 0.93s）。
8. **先 go/no-go 再批量**：先用 g1 跑通“首帧锁形象+爆点动作是否生效”，再批量；已生成的会自动跳过，g1 不会重生。
9. **横屏必 16:9 / 竖屏必 9:16**：画幅 auto_storyboard 已按原片自动判好，写在 storyboard.json，别覆盖。
10. 🛑 **STOP：生成不了或被策略拦的镜 → 停下来把 tradeoff 抛给用户**（换提示词/降速/简化），不要静默降级。
11. **源片只读**，不改不移不删。复刻是“再创作”，结论如实说明非逐帧克隆。
12. **合规两件事别混**：①「破坏调性的免责底注」不加（如满屏小字 AI 警告）；②但「法定 AI 标识」要加——
    真人样貌/换脸成片在国内平台发布，按《AI生成合成内容标识办法》须显著标识：storyboard.json 设 `"ai_label": true`
    或 `FK_AI_LABEL=1`，assemble 会叠角标『AI生成』。换脸只能用本人或已授权的脸；默认生成「虚构人物」最安全。

## 片型覆盖（诚实说边界，别让用户白烧钱）
- **现在做得好**：换装/转场、产品多角度、前后反差、宠物、慢节奏 Vlog —— 画面驱动、单主体。
- **现在弱/做不了**：口播讲解（爆点在台词→画面对不上嘴）、卡点踩拍/高密度快剪（节奏难 1:1）、
  3 人以上互动/复杂剧情（跨镜人物易乱）。遇到这类**先把 tradeoff 抛给用户**（换片 / 接受七八分像），别硬上。

## 密钥 / 后端 / 按脸分流（直接关系到花多少钱）
- 纯 **seedance**，两条后端：**APIMart**（`APIMART_TOKEN`）+ **火山方舟 ARK**（`ARK_API_KEY`）。详细注册/购买/填 key 见 `安装与API配置指南.md`。
- 密钥只从 `_work/.secret.env` 读，已 `.gitignore`，不进代码、不外传。跑前：复制 `.secret.env.example` 成 `.secret.env` 填 key；`pip install -r requirements.txt`；装 `ffmpeg`/`ffprobe`。

**按脸分流（默认，最省）：**
| 镜头 | 走哪条 | 模型 | 为什么 |
|------|------|------|------|
| **无人脸**（产品/场景/清单/空镜） | 火山方舟 | **Mini** | 最便宜；脸弱但这类没脸，无所谓 |
| **有人脸**（人物/换装真人） | APIMart | **Fast** | 脸更稳 |
| 高要求/换脸 | 任一 | Pro | 手动指定 |
- 分流逻辑在 `config.py` 的 `plan_for(kind)`：无脸→`ark/mini`，有脸→`apimart/fast`（`FACE_ROUTE` 可改成 `ark` 让脸也走火山 Fast，同一个 key）。分辨率 `resolution_for()`：人物镜 720p、其余 480p；`FK_RESOLUTION=480p` 整片强制省钱草稿。
- 单镜手动覆盖：storyboard.json 该 unit 加 `"route":"ark|apimart"`、`"tier":"mini|fast|pro"` 或 `"model":"完整id"`。
- 整片强制一条：`.secret.env` 写 `FK_ROUTE=ark`（或 apimart）。
- Mini 的 model id 命名按官方文档为准；首次用 `python -m pipeline.verify_mini` 确认（最小花费），不符就 `.secret.env` 写 `FK_MODEL_MINI=正确id`。
- ARK 与 APIMart 请求体不同，`gen_video.py` 已逐镜按 route 分支（ARK：content/ratio/base64 图、无需图床）。ARK 无图像端点，首帧用宿主内置生图或走 APIMart 生图。
- 换脸进阶：把人脸图作 `reference_image` 喂进去（`gen_video.py` 的 `submit()` 已支持），档位用 Fast/Pro。**换脸只能用本人或已授权的脸**。

## 成本意识（心里有数）
- **价格按 token 扣**（不是按条）：火山方舟 Seedance 是「资源包 / token」计费，建议自己记一笔 token 用量台账，心里有数。
- **省钱三招**：① 无人脸镜走 Mini（最大头）；② 默认 480p（要高清才上 720p/1080p）；③ 少切几个生成单元。
- 参考量级（**以你自己充值后的实测为准，下面是估算**）：Mini 资源包约「1 亿 token ≈ ¥1400」，单价远低于 Fast；
  Fast 约「¥37/百万 token」量级。一条 13s 竖屏 480p 复刻片（5–6 个 4s 单元）通常几元到十几元。
- 第一条贵在开发编排，不是稳态成本——SOP 固化后趋近于零。
