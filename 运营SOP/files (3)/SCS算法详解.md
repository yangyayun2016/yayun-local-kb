# 亚马逊 SCS（Sub Category Score）细分类目排名得分算法详解

> ⚠️ **重要声明**：与CDQ（有官方支持工单给出精确公式）、PQS（官方至少公开了71/19/10顶层权重）不同，**SCS目前没有任何亚马逊官方公开的量化公式**。本文档是基于"哪些徽章/标签/算法信号会实际影响细分类目排名与曝光"这一业务事实，做的工程化建模。所有权重、阈值均标注 ⚙️假设，使用前务必用真实类目的排名/流量数据做回归校准，不能当作官方口径对外引用。

---

## 一、类目三层结构

| 层级 | 示例 | 特点 |
|------|------|------|
| **一级类目（大类目）** | `Home & Kitchen` | 流量极大，竞争惨烈，新卖家/中小listing几乎不可能在此层看到自己的排名 |
| **二级/三级类目（Sub-Category，中类目）** | `Vacuum Cleaners & Floor Care` | 品类相关性开始收窄，部分头部listing可在此层出现排名 |
| **叶节点（Leaf Node，最底层细分类目）** | `Electric Brooms` | **SCS真正发力的层级**——绝大多数排名类徽章（Best Sellers/Hot New Release等）都是在叶节点内计算的 |

**运营启示**：叶节点选择本身就是一种排名策略——同一产品可能适配多个相邻叶节点，节点内竞争ASIN数量差异巨大，直接决定"上榜"的难度。SCS系统里会把叶节点竞争度作为一个可参考的决策因子（而非强行拉高分数的理由）。

---

## 二、9类徽章/标签 —— 判定逻辑与来源

### 排行榜类徽章（叶节点内实时/滚动计算）

| 徽章 | 判定逻辑 |
|------|---------|
| 1. **Best Sellers**（畅销榜） | 叶节点内销量排名，橙色徽章仅授予Top 1（部分类目Top 100均可见排名，但徽章通常只给#1） |
| 2. **Hot New Releases**（新品热销榜） | 上架时间通常 <30天的新品在叶节点内的销量排名 |
| 3. **Movers & Shakers**（飙升榜） | 滚动窗口（通常24小时）内排名涨幅最大的商品，反映短期动能而非绝对量级 |
| 4. **Most Wished For**（心愿单榜） | 叶节点内被加入心愿单次数排名 |
| 5. **Gift Ideas**（礼品榜） | 叶节点/礼品场景策展榜单，常与节日/送礼场景关联，受季节性影响大 |

### 平台算法/官方标签类

| 徽章 | 判定逻辑 |
|------|---------|
| 6. **Amazon's Choice** | 算法基于评分、价格、库存可得性、配送速度，针对**特定搜索词**授予（同一ASIN对不同搜索词可能有/无该标签，不是ASIN级固定属性） |
| 7. **"客户常保留这个产品"标签** | 基于该ASIN的退货率显著低于品类均值的信号 |
| 8. **特色品牌（Featured Brand）标签** | ⚙️据你提供的口径：品牌层面 **≥5000位顾客给予≥92%好评**，且**近期订单量超过1万笔**，同时需有品牌旗舰店/Brand Registry资格 |
| 9. **气候友好承诺（Climate Pledge Friendly）** | 需持有亚马逊认可的第三方可持续认证（如能源之星、Cradle to Cradle等）或满足亚马逊自定义可持续标准 |

> 徽章6-9本质是"信任信号"，直接影响点击率（CTR）与转化率，间接推动排名类徽章的达成——这是SCS系统把它们放进同一体系的原因：两组徽章互为因果，不是并列无关的指标。

## 三、推荐算法信号（非徽章，但同样影响流量分配与排名）

### 1. 传统行为型推荐（协同过滤）

| 模块 | 机制 | 运营抓手 |
|------|------|---------|
| **Frequently Bought Together（FBT）** | 大数据关联：A、B商品共同购买频次达阈值后被系统锁定组合入口 | 通过"买A加购B"广告或Virtual Bundles人为建立强关联 |
| **Compare with similar items** | 系统抓取价格/评分/属性高度相似的商品做强制对比，展示在Listing页面正中间 | 极强流量拦截位，也是ASIN投放广告的必争之地 |
| **Customers who viewed this item also viewed** | 捕捉浏览与对比路径，形成中端考虑流量 | 依赖曝光量基数与关联商品的相似度 |

### 2. 语义与结构化推荐（Rufus / Amazon AI Shopping 导购 + Cosmos语义算法）

**逻辑**：买家用自然语言向Rufus提问（如"我想给猫挑一款好洗、不粘毛的猫窝"）时，Rufus不再做简单关键词匹配，而是读取：
- Listing后台的 **Product Type (PT)** 属性
- **RAC Top 10**（CDQ体系中的前10项核心相关属性，即结构化属性质量维度的数据源）
- A+页面中的物理参数

**加成机制**：Listing属性填写的正确率与完整度越高（即触发CDQ v3高分段），Rufus/Cosmos就越可能在对话框中生成 **"AI Recommended"** 标签并附带高亮小红标——这是当前阶段最顶级的"溢价免费流量"。

**关键结论**：**CDQ的结构化属性质量（30%权重）与SCS的Rufus AI推荐信号是同一份底层数据的两种呈现**——做好CDQ本身就是在为SCS铺路，这也是本系统在代码里直接复用CDQ结构化属性完整度作为Rufus推荐信号输入的原因。

### 3. 促销活动对排名的转化拉动

BD（Best Deal）/ LD（Lightning Deal）/ DOTD（Deal of the Day）/ Outlet 等促销形式本身不是徽章，但通过短期集中转化拉动销售速度（Sales Velocity），间接影响 Best Sellers / Movers & Shakers 等排名类徽章的达成概率。SCS系统中作为"排名助推信号"计入推荐信号维度，而非独立赋分。

## 四、SCS 打分模型（⚙️工程化建模，四大维度）

| 维度 | 内部权重 ⚙️ | 覆盖内容 |
|------|------------|---------|
| **A. 排行榜徽章** | 40% | Best Sellers / Hot New Release / Movers & Shakers / Most Wished For / Gift Ideas，按叶节点内排名百分位打分 |
| **B. 平台AI/信任标签** | 35% | Amazon's Choice / 保留标签 / 特色品牌 / 气候友好承诺，达成即计满分，未达成给0 |
| **C. 类目结构精准度** | 10% | 叶节点是否准确、相关性是否高（竞争度作为决策参考信息，不直接拉分） |
| **D. 推荐算法信号** | 15% | FBT关联强度 / Compare Similar Items胜出率 / Viewed Together曝光率 / Rufus-Cosmos AI推荐 / 促销活动加持 |

**维度A内部权重**（Best Sellers权重最高，因其是唯一"标志性"橙色徽章）：
Best Sellers 30% / Hot New Release 15% / Movers & Shakers 15% / Most Wished For 20% / Gift Ideas 20%

**维度D内部权重**：
FBT关联 20% / Compare Similar Items 20% / Viewed Together 20% / Rufus AI推荐 30%（权重最高，因其代表2026年最新的语义流量入口）/ 促销加持 10%

**排名百分位打分公式**（用于维度A，叶节点内榜单显示通常Top 100）：
```
score = clamp(1 - (rank - 1) / 100, 0, 1)   # rank=1 -> 1.0，rank=100 -> ~0，未上榜 -> 0
```

## 五、SCS 与 CDQ 的关系（⚙️需你自行验证）

你提到"SCS在CDQ有额外10%权重"。需要说明：**这一叠加关系本身也不在亚马逊公开文档中**，本系统按此假设提供了 `to_cdq_bonus()` 换算函数：

```
CDQ加分 = SCS总分(0-100) / 100 × 10   # 最高贡献10分
```

由于原CDQ文档给出的官方分值区间是100-120（含Discoverability 0-20加分），若再叠加SCS的0-10分，总分上限可能突破120。**建议将SCS视为与CDQ并行的独立监控指标**，而非强行加总进同一个数字，除非你有内部数据能验证两者的真实叠加逻辑。

## 六、优先级建议

1. **地基先行**：结构化属性质量（CDQ 30%）做到位，同时喂养Rufus/Cosmos的AI推荐资格——一次投入，CDQ、PQS、SCS三处受益
2. **叶节点选择审慎评估**：避免为了"更容易上榜"选择相关性不足的叶节点，长期会反噬转化率和账号健康
3. **信任标签是杠杆点**：Amazon's Choice、保留标签、特色品牌门槛相对客观（评论数/好评率/订单量），比拼流量运营更"可管理"
4. **促销服务于排名速度**，不建议脱离利润率单独追求BD/LD/DOTD频次
