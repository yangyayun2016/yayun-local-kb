# 待投放（增益）规则 与 词根聚合方法 v1.0

止损解决"怎么少流血"，本篇解决"怎么把优质流量放大"——这是很多止损类 Skill 缺失的另一半。
配合 `stoploss-rules.md`（如项目中已有 amazon-ppc-stoploss Skill）或本 Skill 内置的止损模块一起使用。

---

## 一、待投放候选的判定层级

和止损一样，从细到粗：搜索词 → Target → 词根 → Campaign。
但待投放的落地动作正好相反：不是"关/降"，而是"提价/扩量/新建精准 Campaign 承接"。

---

## 二、规则 A：搜索词层——优质词转 Exact 承接

**触发条件：**
```
Search Term 落在「优质区」（ACOS ≤ 下调阈值 floor，见 formulas.md 五档分区）
AND Orders ≥ 3（样本量足够，不是偶然出单）
AND 该搜索词当前不是以 Exact 匹配方式独立投放（即仍隐藏在 Auto/Broad/Phrase 广告组里）
```

**动作：** `PROMOTE_TO_EXACT`（建议新建/加入 Exact Campaign，独立控价承接）
**理由：** 隐藏在宽泛匹配里的优质词，出价被和一堆无效词混在一起，无法针对性提价抢排名。
独立成 Exact 词后，可以给到比当前更高的 bid，在健康 ACOS 范围内换取更多曝光份额。

**Review Required：** 否（属于扩量动作，风险低于否定类动作，可自动生成建议直接执行）

---

## 三、规则 B：Target 层——提高 Bid

**触发条件：**
```
Target ACOS ≤ 下调阈值 floor
AND Orders ≥ 2
AND 展示量份额未饱和（Impression Share < 80%，如报表提供该字段；无该字段则用"点击量周环比仍在增长"替代判断）
```

**动作：** `RAISE_BID_10` 至 `RAISE_BID_20`（建议提高 10%–20%，小步测试，不建议一次性大幅提价）
**Review Required：** 否

**触发条件（激进版，仅在牺牲比例 sacrifice_ratio > 100% 即"愿意亏本换排名"模式下启用）：**
```
Target ACOS ≤ target_acos（健康区也算，不必是优质区）
AND 该产品处于新品冲排名/大促蓄流量阶段（由用户在规则配置阶段声明）
```
**动作：** `RAISE_BID_30`，同时标记「该建议基于牺牲比例>100%的激进配置，非常规盈利判断」

---

## 四、规则 C：Campaign / 预算层——提高日预算

**触发条件：**
```
Campaign 预算打满率 = 100%（连续 ≥ 3 天）
AND Campaign ACOS ≤ target_acos（健康区或优质区）
```

**动作：** `RAISE_BUDGET_20` 至 `RAISE_BUDGET_50`
**理由：** 预算是当前唯一瓶颈，ACOS 表现健康说明有更多"性价比订单"没有被承接到，
不提预算就是主动放弃这部分免费增量。

**Review Required：** 否，但建议提预算后第二天必须复查 ACOS 是否维持健康（预算放开后流量结构可能变化）。

## 五、词根聚合（Root Clustering）方法

### 5.1 为什么要做词根聚合

单个 Search Term 的样本量往往不够（比如 "insulated lunch bag for women" 单独只有 8 次点击，
不够判断），但如果把所有包含「insulated lunch bag」这个核心词根的搜索词汇总，
点击量可能有 200+，统计意义就出来了。词根聚合能：

- 发现"个体样本不足、但整体表现优异"的隐藏流量池 → 待投放
- 发现"个体看似正常、但整体在烧钱"的系列词 → 一次性否定整个词根系列，而不是逐条否
- 为新建 Exact/Phrase Campaign 提供选词依据

### 5.2 词根提取算法（简化版，脚本内实现）

```
1. 分词：按空格切分 Search Term（英文场景）
2. 去停用词/修饰词：for / with / the / a / an / of / and / set / pack /
   size / color / small / large / new / best 等（清单可在规则配置中扩展）
3. 保留核心名词短语：通常是去停用词后剩下的 2–3 个连续词
4. 归一化：转小写、去复数简单归一（bags → bag，仅做基础处理，不追求 NLP 完美）
5. 按归一化后的核心词组分组（即"词根"），汇总该组下所有 Search Term 的：
   Impressions / Clicks / Spend / Sales / Orders
6. 重新计算词根层级的 CTR / CVR / CPC / ACOS
```

> 中文场景（如有中文站点）：改为按关键 2–4 字词块切分，去掉"的/和/与/装/款/个"等虚词，
> 逻辑同上，脚本中提供中英文两种简化分词模式。

### 5.3 词根层级判断

对每个词根，套用与搜索词层完全相同的五档分区规则（见 `formulas.md` 第六节），
但阈值判断放宽——因为词根是聚合样本，天然更可信：

```
词根整体 ACOS ≤ floor 且 Orders ≥ 5      → 待投放：新建 Exact/Phrase Campaign 承接该词根
词根整体 ACOS > breakeven 且 Orders = 0   → 止损：整个词根加入否定候选（比逐条否更彻底）
其余                                       → 维持当前投放结构，继续观察
```

**输出字段：**

| 词根 | 覆盖搜索词数 | 汇总 Clicks | 汇总 Spend | 汇总 Orders | 汇总 Sales | 词根 ACOS | 分区 | 建议操作 |

|-------------|--------|-------------|------|--------|------|---------|---------------------|-----------------|

**安全机制（与止损模块一致的克制原则）：**
- 待投放的提价/提预算动作，单次幅度不超过 20%（激进模式除外，且必须用户在规则配置阶段显式声明）
- 新品保护期内的对象即使表现优异，也先标记「观察」而非直接扩量，避免样本量不足导致的误判
- 提价/提预算后必须在下一次诊断中复查，不是"一次性动作"，而是"小步快跑、持续验证"
