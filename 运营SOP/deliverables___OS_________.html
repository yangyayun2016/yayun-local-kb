01先定性：看板是决策容器，不是报表

设计第一原则

现在最危险的不是没有数据，是数据太多。后台、ERP、广告、第三方工具、商机探测器、ABA……每一处都能导出几十个字段。如果直接照搬成图表，你得到的是一面「数据墙」，运营每天刷一遍、什么也决定不了。所以先把定性和约束写死，后面四块看板才有共同地基。

① 一屏一决策

一块看板只回答一个问题。经营看板回答「今天要不要我介入」，账务看板回答「这笔钱到底赚没赚、什么时候到」，关键词看板回答「单为什么少了、明天加哪个词」，异常看板回答「现在先处理哪一件」。回答不了的问题，不属于这块看板。

② 结论先行，证据在后

每块看板严格三层：结论区（要不要动手）→ 证据区（凭什么，趋势/对比/快照）→ 归因区（具体到 ASIN / 关键词 / 订单 / 货件）。任何结论必须能一层层点到底层明细，点不下去的结论就是猜测。

③ 粒度必须匹配动作时延

你要在 1 小时内动手的事才用小时级数据，4 小时内动手的用 6 小时粒度，明天才动手的用天，改结构用周，复盘用月。这就是你说的「小时 > 天 > 周」的真正含义：不是越细越好，而是粒度和动作对齐。小时级数据贵、噪声大、最容易误报。

④ 口径先行，标签随身

每个数字上线时必须带四件行李：时间窗、统计口径、数据截止时间、可信度。转化率是「广告点击口径」还是「会话口径」，IS 是份额不是比率，利润是「结算口径」还是「估算口径」——不带标签的数字一律不允许出现在看板上。

⑤ 数据找人，不是人找数据

看板的默认状态不是「一张随时可查的图」，而是一个已经排好序的队列。人打开看板，是来确认和处理，不是来探索。所有「探索」都发生在下钻里，不发生在首页。

⑥ 看板不新增业务模块

这一条是给工程看的：四块看板是视图层 + 规则层，挂在选品/运营/广告/领星五个板块之上，不重复建设数据。看板本身不产生新数据，只产生判断、任务、动作、留痕。

02指标骨架：L0 到 L4，五层拉直

所有看板共用一套主干

四块看板要能互相对账，就必须共用一套指标主干。不共主干，就会出现「经营看板说涨、账务看板说亏、关键词看板说流量在掉」的经典混乱。下面是建议的五层骨架，每层只放该层该管的东西。

L0北极星净利（月）· 现金（可动用）· 目标达成率 —— 只给老板，只放两三个
L1结果层GMV、订单、销量、ASP、会话、转化率、回款额 —— 回答「发生了什么」
L2结构层站点 / 品类 / ASIN / 价格带 / 新老品 / 自然vs广告流量结构 —— 回答「哪一块在拖」
L3因果层关键词、排名、广告位、竞品位次、评分评论、价格、库存、Buy Box —— 回答「为什么」
L4风险层异常事件、红线越界、合规到期、资金风险 —— 回答「什么时候必须动手」
一个硬规矩：L0/L1 只允许出现在经营看板顶部；L2 是四块看板的公共拆解维度；L3 只进关键词流量看板和下钻页；L4 全部汇总到异常看板。违反这个分层，看板就会退化成「什么都有、什么都没结论」。

04通用设计规范：搭积木怎么搭

四块看板共用

你说的「搭积木」，落到工程上就是：卡片 = 积木，看板 = 布局配置。积木只有 9 种，每种声明自己的数据契约；看板只是把积木摆上去、设阈值、连下钻。这样新增一块看板不需要开发，只在中控台拖拽配置。

九种积木（够用，不要多）

积木回答的问题典型位置数据契约要点
结论卡目标达不达？落点在哪？看板最顶部目标值 / 实际 / 预测落点 / 缺口 / 数据截止时间
拆解卡差在哪一块？第二层贡献项必须加总等于总变动，交互项单列
趋势卡在变好还是变坏？第二层同比基期、异常点标注、缺数据断点不补零
漏斗卡卡在哪一步？关键词 / 商品健康各段绝对量 + 段间转化率，自然/广告分色
队列卡先处理谁？右侧或底部按影响金额 × 时限排序，可认领、可跳转
矩阵卡该往哪个方向走？结构分析X/Y 轴定义 + 阈值线必须在卡片上写明
日历卡什么时候到/什么时候发？账务 / 供应链事件 + 金额 + 状态 + 责任人
证据卡凭什么这么说？下钻层快照日期、样本量、口径标签、原话不改写
简报卡一句话结论是什么？顶部或侧栏三段式（发生了什么/为什么/建议）+ 依据引用 + 置信度 + 采纳反馈按钮

每块积木上线前必须填的 8 个配置项

卡片ID · 类型 唯一问题 —— 这块积木回答什么（写不出来就不做） 指标集 —— 引用指标层的哪些指标（禁止卡片内自写公式） 筛选与时间窗 —— 站点/店铺/ASIN + 日/周/MTD + 对比基期 阈值与分级 —— 绿/黄/红三条线（全部来自设置板块的阈值中心） 排序与截断 —— 按什么排，只显示前 N 条 下钻目标 —— 点进去到哪个工作台、带什么参数 动作按钮 —— 这块积木能直接触发什么（调价/否定/开 case/派单） 空态与降级 —— 没数据时说什么：「样本不足，本日不评分」

空态文案不是小事。缺数据时显示 0 会直接导致误判和误报，必须显式说「不知道」——这就是「标 U 不评分」在看板上的落地。

三条显示纪律

红黄绿只表达「要不要动手」

颜色不是装饰，是行动信号。黄色 = 今天看一眼，红色 = 现在就得动，灰色 = 数据不可用。不要用颜色表达「趋势好看」。

每个数字都带时间戳

看板右上角固定一行：数据截止 10-21 23:00 · 结算数据截止 10-18 · ABA 周更至 W42。看的人要知道自己在看哪一天的世界。

没有对比就没有数字

任何单值旁边必须有参照：目标 / 上期 / 同类目 / 竞品。孤立数字只会让人凭感觉判断，而感觉在这行最容易错。

05看板① 经营看板（每人一个）

角色：老板 / 运营负责人 · 刷新：日 + 盘中

定位与唯一问题

唯一问题：今天这个生意需不需要我介入，介入哪一件？ 它不负责解释原因（交给关键词看板和账务看板），也不负责列所有异常（交给异常看板）。它只做三件事：告诉你目标走到哪、偏差在哪、现在最该处理哪一件。

页面骨架（8 个积木）

①目标落点条 · 结论卡 ×4本月 GMV / 毛利 / 净利 / 回款：实际 + 完成率 + 预测月末落点 + 缺口（这是重点，不是进度条）
②今日战报昨日 vs 上周同日 vs 去年同日：订单 / GMV / 转化 / ASP / 广告占比
③GMV 驱动拆解连环替代：流量贡献 / 转化贡献 / 客单贡献 / 交互项（必须加总闭合）
④板块健康灯 ×6选品 / 运营 / 广告 / 库存 / 账务 / 合规，每灯一个 0–100 分 + 一句主因
⑤今日待办队列5 条，按「影响金额 ÷ 时限」排序，可认领、可派单、可跳工作台
⑥AI 经营简报三段：昨天发生了什么 / 为什么 / 今天建议做什么（每条带依据链接和置信度）
⑦结构小卡站点 / 品类 / 价格带 / 新老品 占比与环比
⑧目标进度OKR 到 KPI 的拆解：目标 → 板块 → 负责人 → 当前进度

核心算法：GMV 变化怎么拆才闭合

GMV = Sessions × CVR × ASP ΔGMV = ΔSessions·CVR₀·ASP₀ + Sessions₀·ΔCVR·ASP₀ + Sessions₀·CVR₀·ΔASP + 交互项 注：交互项必须单列显示，否则三项相加不等于总变动，运营会立刻失去信任。

口径提示：Sessions 用卖家后台业务报告会话数（去重口径）；CVR = 已订购商品数量 ÷ 会话数，不是广告点击转化率；ASP = 净销售额 ÷ 订单数（扣退款后）。三个指标必须同站点、同时间窗、同币种。

「每人一个」怎么实现：不是五套看板，是一套看板五个锚点

很多人把「每人一个」理解成给每个人做一块不同的看板，结果是维护五套口径。正确做法是：同一套积木、同一个指标层，只换锚点和默认阈值。打开时第一眼看到的东西不同，但所有数字同源。

角色首屏锚点默认时间窗默认红黄线常用动作
老板月末落点 + 净利 + 现金MTD + 预测完成率 <95% 红找人、定优先级、拍板
运营负责人今日待办 + 板块灯昨日 + 近 7 日单 ASIN 掉 30% 红派单、调价、改 listing、开 case

AI 简报怎么写才不像废话

模板（固定在 3 句以内）：
① 事实：「昨日 GMV 3,240€，低于近 28 天均值 18%，主因是 DE 站 A 款 Sessions 掉 41%（一次广告活动预算在 10:40 烧完，自然位从 3 掉到 9）。」
② 影响：「按当前速度，本月缺口扩大到 2.1 万€，净利影响约 4,400€。」
③ 建议：「今日 12:00 前：该活动预算 +40%，同时把 2 个高花费零单词否定；预计 3 天内回到均值（置信度中）。」
每条结论后面挂依据链接（点开就是证据卡），末尾给「采纳 / 修改 / 驳回」三个按钮——这三个按钮就是阶段②的采纳率数据来源。
反模式：不要做「20 个图表拼成的一屏」。图表超过 6 个，人的注意力就散了；也不要把「数据都能看」当成目标，那是数据仓库的事，看板的目标是让人今天就做完那个决定。

06看板② 账务回款利润

角色：财务 / 老板 · 刷新：日（估）+ 结算后（实）

定位与唯一问题

唯一问题：这个月到底赚了多少钱、钱在哪、哪一单在亏、什么时候到账？ 这块看板最容易做成假账，因为它同时存在三套口径：业务口径（下单日）、财务口径（结算日）、现金口径（回款日）。大部分「利润对不上」不是算错，是三个日期混在一起用。

设计核心一：三层利润，一次说清

L1 商品毛利

售价 − 采购 − 头程 − FBA 配送 − 平台佣金 − 其他平台费

回答：这个产品本身赚不赚。这是定价与选品的底线，也是保本 ACOS 的来源。

L2 经营净利

L1 − 广告 − 促销/优惠券 − 仓储（含长期）− 退货处理 − 汇损 − 工具订阅 − 分摊人力

回答：这个生意赚不赚。经营看板的「净利」必须取这一层。

L3 现金

L2 − 库存占用资金成本 − 未回款（应收）

回答：我手上有没有钱。很多卖家 L2 是正的、L3 是负的，这就是「账面赚钱、现金紧张」。

设计核心二：四个日期桥（解决 90% 的对账吵架）

日期含义谁用它典型坑
下单日买家下单时间经营看板、广告归因跨月订单导致两个看板月度数字不同
发货日实际出库时间库存、成本结转预售/延迟发货时与下单日错月
结算日亚马逊结算周期入账财务利润表、费用明细费用在本期、收入在下期，毛利虚高
回款日打款到收款账户现金流、资金计划储备金/账期导致「赚了但没到」
工程做法：订单明细表里四个日期同时落库（不是四张表），任何口径都能用同一张明细聚合出来。这一条做到了，「利润表 vs 结算单 vs 银行流水」的差异会从「天天吵」变成「系统自动标出 3 条待查」。

页面骨架（10 个积木）

①L1 商品毛利金额 + 毛利率 + 环比
②L2 经营净利金额 + 净利率 + 目标差
③L3 现金可动用 + 在途 + 储备金
④成本瀑布售价 → 逐项扣除 → 净利（每项可点击看明细）
⑤单位经济卡（核心接口）单 ASIN：售价 / 成本 / 边际贡献 / 保本 ACOS / 目标 ACOS / 保本 CPC → 直接输出给广告板块
⑥SKU 利润贡献TOP / BOTTOM 各 10，含销量×毛利率四象限
⑦回款日历未来 14/30 天预计到账，按结算周期与储备金推算
⑧余额构成可用 / 储备 / 待结算 / 在途，含负余额告警
⑨结算差异对账预估 vs 实际，按原因码归集（退款/费用调整/赔偿/仓储/汇率）
⑩现金周期库存天数 + 应收天数 − 应付天数 = CCC，按月趋势

设计核心三：成本分摊与可信度分级

分摊规则必须先定死

  • 采购/头程：按 销量 分摊（不是按销售额）
  • 广告费：按 广告归因订单 分摊到 ASIN
  • 仓储/退货：按 实际发生 归属，不摊
  • 人力/工具：按 GMV 或 SKU 数 分摊，单列一层「分摊成本」
  • 汇率：收入用 结算日汇率，成本用 下单日汇率，差额进汇损行

影响金额怎么估（决定排序，必须有）

流量/链接类：损失 = 日均订单 × 缺量比例 × 单位边际贡献 × 预计持续天数 花费类： 损失 = 超支额 + 低效花费（花费 × (1 − 目标ACOS ÷ 实际ACOS)） 库存类： 断货损失 = 日均销量 × 缺货天数 × 单位边际贡献 冗余损失 = 库存金额 × 资金成本率 + 长期仓储费 利润类： 损失 = 差额绝对值（直接可算）

有了金额，「先处理哪件」就不再靠感觉，而是按 € / 天排序。这是异常看板从「告警列表」升级为「优先队列」的唯一办法。

11风险与红线

动手前先认下来
口径混用是最大风险。转化率（会话口径 / 广告点击口径 / 商机探测器口径）、IS（份额不是比率）、利润（结算 / 估算）—— 三处混用一次，整套看板的信任就没了。对策：数字必须带口径标签，跨源比较先对齐分子分母。
小时级数据是估计，不是事实。自然排名没有官方小时数据，6h/12h 全靠采样。用它做卡位判断可以，用它做月度结论不行。对策：标采样频率与样本量，样本不足标 U。
AI 只读 + 出草稿，不代操作后台。所有建议必须带依据、置信度、可回滚。敏感内容（成本、供应商、账号）最小化外发。
自动执行必须能一键回滚。没有回滚路径的动作，一律留在人工确认。
阈值都是起点，不是真理。本文所有数值（10 次点击、−40%、200€/天、权重 25/20/15/10/20/10）都是建议初值，需按你的体量跑 4 周后校准，并进阈值中心留痕。
1P 与 3P 不能混算。VC 的 PCOGS / CP / CM 口径与 3P 完全不同，必须独立建表、独立红线，否则利润会算出一个既不对 3P 也不对 1P 的第三个数。（你在学 VC，这一条尤其要守住。）

12下一步：三个可以立刻做的动作

不用等系统

① 先定 20 个指标的口径

不用 45 个。把 GMV、净销售额、会话、转化率、ASP、毛利、净利、广告费、ACOS、TACOS、可售天数、退货率、评分、BSR、Buy Box 占比、展示份额、自然位、广告位、出单词数、重叠词数——这 20 个的口径先写死，后面的看板才有根。

② 用 Excel 先跑一周「异常队列」

不开发，先把六类异常里最贵的 10 条规则，用现有导出数据手工跑一周。看有多少条真、多少条假。真实率不到 60% 的规则，先别写进系统。

③ 把保本 ACOS 算到 ASIN 级

这是整条链路里杠杆最高的一件事。算出来之后，广告、异常、利润三块看板同时有了标尺，而且立刻能发现一批「一直在亏着投」的词。

一句话总结：四块看板的价值不在「看得全」，而在「看完就知道今天做什么」。经营看板给方向，账务看板给底线，关键词看板给原因，异常看板给动作。四块连起来，才叫决策回路；分开摆，就只是四张报表。
